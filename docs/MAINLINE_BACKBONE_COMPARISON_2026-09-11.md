## 两个接口问题及处理

Sol 在 VID103_18501、VID23_28551 的 H0 遭 OpenRouter/OpenAI 上游 403，原文原因 `violence/graphic`。
响应明确写明未扣费。保留失败目标，未修改医学用途说明、图片或提示来绕过拒绝，也没有补调 H0。
该问题属于当前路由的可用性，不能等同于模型看图判错。

Qwen 请求别名 `qwen/qwen3.8-max`，六次 HTTP 200 都返回 `qwen/qwen3.8-max-0902`，
被原传输层的严格字符串一致校验标成 FAILED。其内容已是有效 H0，不是模型没有回答。
公开 alias 与 snapshot 的端点元数据均指向 `qwen/qwen3.8-max-20260902`、Alibaba、相同价格。
恢复入口核对六份原始请求、图像指纹、响应模型、provider、finish_reason 和五头 schema，
复用这六份真实 H0，后续基座请求显式固定 `qwen/qwen3.8-max-0902`，仅补此前未派发的 12 步／目标。
原账本与原响应不改；别名拒绝作为工程事件保留，复合评分明确标记已核验恢复。
这是别名处理修复，不是换模型重跑或按 GT 挑选回答。

Qwen 的耗时必须标注为“原 H0 HTTP 耗时 + 后续修复墙钟耗时”的重建累计值，
不是一次连续的三方同负载延迟测量。因此不宣称精确加速倍率。
本轮 Qwen low reasoning 与此前关闭思考的阿里云 Batch 基线配置不同，不能混用成本或成绩。
