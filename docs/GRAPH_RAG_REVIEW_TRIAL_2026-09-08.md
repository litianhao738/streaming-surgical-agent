# 独立 GraphRAG 审核对照（2026-09-08）

状态：独立实验已部署，6 个 Training 目标的 102 次真实请求、独立评分与审计完成。**本批没有检索带来的额外 Target／IVT 收益，图检索还少补回一个正确 Verb，因此不切换默认版本。**默认 H0、已有 Verifier／Repair 入口、历史结果和训练输出均未改动。

## 本次实现的范围

这是针对候选池的轻量本地图检索，不是 Microsoft GraphRAG 全套部署。无模型训练、embedding 服务、图数据库或额外检索 API。

```
三张因果图片 → 共享 H0 → 共享单模型补候选 → 固定同一候选池
                                         ├─ 不检索 → 原五席审核 → 原规则修复
                                         ├─ 文本检索 → 原五席审核 → 原规则修复
                                         └─ 图检索 → 原五席审核 → 原规则修复
```

新增资料只放在 `make_pool` 之后、五席审核之前。五席仍并行；模型、图片、输出模板、输出 token 上限和均分阈值 4 不变。本次每组仅一轮，以隔离检索的作用，不混入多轮候选变化。

每席只增加 `reference_knowledge` 输入字段，不要求模型增加输出说明。最多 4 条去重资料、每候选最多 2 条，整个参考包按实际 JSON 空格格式不超过 2500 字符。图检索最多走两条边，例如“某个完整 IVT → 该 IVT 的动作 → 动作边界说明”。图不会制造新的 IVT、扩大候选池、打分或修改最终标签。

知识图有 100 个完整 IVT 节点、32 个组件节点和 8 条可追溯说明。**这 8 条都已经存在于旧审核 prompt 中。**本实验检验的是“按候选检索和重新组织已有说明”，不能声称加入了新的医学知识、官方标注细则或训练集经验。原文来源、摘录哈希、图关系及未被长度预算覆盖的候选均留档。两种检索共用同一语料和长度上限；普通文本检索按词项相关性取资料，图检索按明确的节点关系取资料。

本版不使用任何视频 GT 统计、参考图片、模型反思记忆或跨视频案例，因此不存在查询目标读取自己 GT 的检索路径。评分独立进行，缺失 GT 按任务 mask 排除。未来如果加 GT 统计或案例，必须另行落实按视频／评估 fold 留出，不能沿用本版的无 GT 声明。

## 具体发生了什么

唯一不同的是 `VID103_18601` 的 `verb_0 / grasp`。候选池完全相同，原修复和普通文本检索的五席均分均为 4.4，达到阈值 4，补入正确的 grasp；图检索的五席分数依次为 **4、3、3、1、5**，均分 3.2，因此没有补入。

这不是 JSON 缺字段或 Repair 把标签 ID 映射错。归一化、均分、阈值与局部修复代码都按既定规则执行。模型在相同图片、不同参考文字下，对 grasp 与 retract 的判断发生分歧。某个模型写出的“更像牵拉”等说明只是其判断，不能作为视觉真值；单次调用也无法区分参考文字效应与模型输出波动。

图检索确实改变了取资料的方式，例如沿完整 IVT 的 Target 组件找到直接操作目标定义，并减少词面检索命中的无关 null 说明。但它没有提供新图像、额外接触证据或新知识，仍由原五席看图。更相关的说明没有在本批转化为 Target／IVT 净收益。

共享候选池也形成了明确上限（下表按六帧标签出现次数累计，不是去重后的类别数）：

| 任务 | GT 正例数 | 池中已有 | 池外漏检 | 池内仍未选中 | 最终正确预测 | 最终错误预测 |
|---|---:|---:|---:|---:|---:|---:|
| Target | 11 | 9 | 2 | 2 | 7 | 5 |
| IVT | 12 | 7 | 5 | 3 | 4 | 8 |

三种审核的 Target／IVT 最终集合完全相同。**5/12 的真实 IVT 根本没进候选池**，本版放在候选固定之后的 GraphRAG 没有权限把它们加回来。池内仍漏掉的真实 Target／IVT，即使只看五席原始数值，均分也低于 4；不能把这些漏检归因于解析器丢掉了本来足以通过的正面判断。

102 次回答都成功解析，并不等于每项证据都有效。每组共 310 个“候选 × 审核席”判断，无检索有 23 项、文本检索 29 项、图检索 28 项未通过证据规则。图检索的 28 项全部涉及“只否定了局部实例，却不足以否定整帧标签”。历史归一化外层把这些统称 `SCHEMA_INVALID`，具体原因在 `format_diagnostics` 中为 `LOCAL_ABSENCE_CANNOT_DELETE_FRAME_LABEL`，本批不能据此归因于 JSON 格式错误。

18 个面板最终都为 `UNRESOLVED`：原规则仍可应用部分已通过的修改，但这不代表整帧五席认证通过。本对照冻结为一轮，未因看到 GT 分数而临时追加反思或循环。

相对无检索，图检索五席输入 token 增加 **8.63%**，本批审核美元费用增加 **5.18%**、人民币估算增加 **4.69%**。输出 token 同时发生变化，因此这些是实际小样本账单差值，不是单纯文字长度的固定报价。

本次 102 请求合计：OpenRouter **$0.16255344**、xAI **$0.367128**，美元合计 **$0.52968144**；阿里云 **¥0.194486**（按 token 保守估算，非账单原生金额）。84 次有原生美元费用、18 次为人民币估算，无未知费用占位，也没有自动重试。

## 核验与保留决定

43 项相关测试通过，新增 Python 文件 Ruff 通过。独立审计核验了 60 组逐席请求对照只相差 `reference_knowledge`、18 个面板从原回答到最终标签的重放一致、20 项评分表及 5 组修改统计、费用与原始 usage 一致，以及冻结源文件、图片和原入口未改变。

结论：**保留无检索的原修复版本；GraphRAG 仅作为独立实验保留，不默认启用。**本结果仅否定“这份既有定义的短图检索包在本批带来额外收益”，不能扩大为所有 GraphRAG 都无效。下一步若继续研究，应先明确有什么可信的新信息可供检索，而不是仅扩大重复资料、提高 token 上限或增加循环次数。
