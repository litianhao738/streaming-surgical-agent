# 明确审核对象：新的 Training 对照与 Validation 确认协议

状态：推理前协议。用户授权在六小时内继续寻找和实测可行修复方案，本轮新增 API 总额度不超过 12 美元。历史实验费用另列。当前文件不宣称方案有效，也不修改默认纯 H0。

## 已核实的问题与本轮变量

24 目标历史实验排除 300 字符限制后，新审核仍未提高 IVT：A 与 H0 相同，B 的 IVT micro-F1 为 25.00%，低于 H0 的 26.83%。其中出现过命题的器械与审核文字所检查的器械不一致、反证对应到其他器械的问题。原始请求确实含完整且正确的 100 类本体，不能称为本体缺失，也不能证明数字编号是全部错误的原因。

本轮唯一审核输入变量是：由 Python 从冻结本体确定性展开争议标签的名称，IVT 展开完整 instrument / verb / target 元组。旧数值命题与新名称命题共享 H0、定位、候选、图像、完整本体、输出 Schema、1000 字符上限与 A/B 接纳规则。系统视觉说明保持一致。不向审核展示 H0/H1 身份或 ADD/REMOVE 方向。

这属于待验证的接口修正，不是新增视觉证据；图片引用、文字说明与模型自报的全图检查仍不能自动证明视觉结论正确。

## 修复机制

1. 冻结 H0 通过原版三帧联合请求生成五头标签。
2. 盲定位与候选阶段各运行一次，生成 H1；本轮无需旧双假设审核。
3. Python 求 H0/H1 各头的集合差异，生成与增删方向无关的存在性命题。
4. 同一组图片分别送入数字命题审核、名称命题审核，变体执行顺序随目标交替。
5. Verifier 返回 PRESENT / ABSENT / UNCLEAR。增加标签需要 PRESENT；删除需要 ABSENT 且满足全帧证据约束；UNCLEAR 不允许修改。
6. A 要求全部修改通过才接纳 H1；B 从 H0 开始，仅执行获准且满足依赖的局部修改。删除 IVT 不级联删除组件；添加 IVT 所需组件必须已存在或独立获准；组件不能被删除到与保留 IVT 冲突。Phase 保持 H0。

B 是本轮主要修复输出，A 作为保守对照。候选无效、审核失败和无变化目标均保留在整体分析中，不按结果删样。

## 样本与数据边界

只按官方 split、时间分位、历史目标排除与任务 mask 检查选样，不用标签类别或错误分数选样。源清单保存在 `artifacts/preflight/verifier_goal_readiness_20260907/`，执行时另行冻结清单及输入/源码哈希。

- Training：VID103、VID23、VID31、VID96 各 4 个新时间目标，共 16 个。Instrument / Phase 有效 16，Verb / Target / IVT 有效 15。缺标注目标不换样。
- Validation：VID110、VID30 各 4 个时间目标，共 8 个。Instrument / Phase 有效 8，Verb / Target / IVT 有效 4。该 IVT 结果仅覆盖 VID110 的四个有效目标，不能写成八帧完整 IVT 或跨视频 IVT 验证。
- 历史已请求目标前后 50 原始帧排除；窗口只用真实可用因果图片。Testing 不参与。
- 新预测全部保存后再关联当前批 GT 算分。Validation 标签值在方案冻结前不读取；看过确认成绩后不据此继续选方案。

## 调用与预算

模型保持 `qwen/qwen3.8-max-0902`、严格 Alibaba、temperature=0、reasoning=low、max_tokens=4096，同步 OpenRouter，非 Batch。

Training 基础采集最多 48 次 POST（16×3），两种审核最多 32 次（16×2），合计最多 80 次。无变化/不可用候选不调用审核，无自动重试。若 Training 后选定方案，再冻结单一审核版本，Validation 最多 32 次（8×4）；A/B 共用一次审核，不增加调用。

所有新付费阶段共用追加式费用账本。全目标上限 12 美元，开发阶段上限 8 美元，为确认阶段保留余量。派发前按最新公开元数据预留每次请求 2.60 美元：1,000,000 上下文 token × 最高输入单价 0.0000025 美元 + 4096 输出 token × 0.000006 美元 = 2.524576 美元，向上取整。该预留远高于历史实际请求，不是预计实际单价。响应原生费用可核实后结算差额；失败或未返回费用不当免费，继续占用预留。串行派发，不靠未结算退款继续调用。价格上涨、身份变化、认证/余额错误或预算不足停止派发。

公开定价快照：`pricing_20260907_0240.json`。这是基于当前定价与请求上限的客户端控制，不声称设置了供应商账户硬限额。

## 评价与后续决策

同时报告 H0、未经审核的 H1 策略、数字 A/B、名称 A/B：各头 TP/FP/FN、micro-F1、集合 Accuracy、有效 GT 数；逐目标完整改对、部分改善、改坏、mixed、等损失替换、保持；各头有益/有害修改应用率；失败回退与新增费用。

核心问题是名称审核是否更可靠地区分有益/有害修改，以及局部修复是否产生 IVT 净收益。全部 KEEP、格式合法率或说明更长不算成功。统计候选共同漏检与理想选择上限，避免把候选不足归责于审核，或反过来掩盖审核错误。

无论这批分数如何，均不凭少数 Training/Validation 样本自动替换默认 H0。若未发现语义收益，就如实保存负结果。若继续另一个机制，必须先由这批错误类型说明理由，另写新协议和源码版本，不覆盖本轮，也不使用 Validation 结果调参。

## Memory / reflection 的位置

目前不实现跨帧预测记忆或自由反思循环。可供后续独立检验的是：有来源的类别定义卡（解决定义混淆）；真实因果历史图片或轨迹线索（解决时间/定位信息不足）；由可检查的具体矛盾触发、最多一次的针对性复核（解决对象或逻辑关联错误）。三者都必须产生额外可用信息或可检验约束，不能仅把先前模型判断写成“已确认事实”。

CoVe 提供拆分具体核验问题的思路；CRITIC 强调工具反馈；Reflexion 用任务反馈形成记忆。相关论文的任务和反馈条件不同，不能直接证明它们会改善手术 IVT。当前项目的首个实测变量仍是程序展开名称。
