# Tracker 零新增模型调用：器械头融合

结论：针对用户要求“保留现有 PGP-Gate、不给大模型新增调用、尽量简单”，推荐将 Tracker 用作器械专家，在原 PGP 输出后做一次纯 Python 合并。本轮已在现有 6,059 帧缓存上验证，未修改默认或模型，未调用 API。

## 最简流程

```text
三帧图像 → 原 PGP 流程 → 原五头结果
当前帧 → 冻结 Tracker → 器械类别集合
最终 instrument = Tracker 检出的类别 ∪ 原 IVT 中需要的器械类别
其余 verb / target / IVT / phase = 原 PGP 结果
```

采用原冻结检测阈值，不重新训练或搜索阈值。使用当前帧实际检测类别，不将历史出现等同于当前存在，也不把关联 ID 作为类别投票。

保留 IVT 所需的器械，避免单纯替换 instrument 后出现“输出某 IVT，但其器械不在 instrument 中”的新矛盾。现有输出 schema 最多允许 3 个器械类别；融合超过该上限时保留原 PGP 输出，不根据 GT 排序、放宽上限或随意截断。本轮 17 帧因此回退。

运行时若 Tracker 不可用或来源/帧对齐校验失败，应回退原 PGP 结果。AVAILABLE 但当前帧没有检测是另一种状态，不能与读取失败混淆。

PGP 使用已保存的外层按视频留出路由；Tracker 使用冻结 OOF 索引对应的预测。基线精确复现既有 61.698902% / 36,150，不能与最终全量拟合模型的训练集回放混用。

## 简单对照也完整保留

仅比较三个固定公式，没有训练或阈值扫描。容量超限统一回退原输出。

| 固定公式 | 五头 F1 | FP+FN | IVT 中器械未出现在 instrument 的帧数 |
|---|---:|---:|---:|
| 原 PGP | 61.6989% | 36,150 | 12 |
| instrument 直接替换成 Tracker 类别 | 63.1310% | 34,784 | 669 |
| 原 instrument 与 Tracker 取并集 | 62.6632% | 35,333 | 2 |
| **Tracker 类别与原 IVT 器械取并集** | **62.8511%** | **35,113** | **0** |

直接替换分数更高，但引入很多器械与 IVT 的不一致。推荐的公式在分析脚本中事先标为主设计，理由是保留原 IVT 所需器械；不将其包装成所有指标的绝对最优。

## 结论边界与复现

- 本轮是反复用于开发的四个 Training 视频上的事后固定规则比较，不是新的独立确认；上游先验和 Tracker 没有在 Gate 每个外层中完全重新嵌套。
- 使用的是 Tracker 的检测类别输出。本公式不消费跨帧 ID，不能声称时序关联提高了识别，也不能称为 IVT 修复。
- 预测 GT 只用于离线评价；融合函数只接收原预测与 Tracker 类别。
- 基线逐帧 TP/FP/FN 与已冻结数组一致，所有变体其他四头完全不变，Tracker 输入文件哈希与 OOF 索引一致，输出通过原 schema 检查。
- 新增 API 为 0，旧默认和权重未改。前一份新增两次调用的设计被本轮简单方案取代为当前建议，旧设计保留历史记录。
