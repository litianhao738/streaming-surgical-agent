# 中性标签存在性审核：24 目标固定对照协议

本轮由用户明确授权继续测试，费用不作为停止条件。开始前的判断是：先前两个旧目标的小测暴露了“反对删除”被程序解释成“标签不存在”的接口歧义，值得先修正该歧义，再用新目标检验 A/B。此次不反复调整视觉提示，不引入 Tracker、Gate、额外模型、跨窗口记忆或多轮修复。

## 唯一语义改动

新增独立版本 `frame_label_presence_review_v2`；旧 `frame_label_diff_review_v1`、旧双假设审核和历史实验保持可复现。

新 Verifier 只收到中性命题，例如“目标帧是否存在该类别的交互”，返回 `PRESENT / ABSENT / UNCLEAR`。命题 ID 不编码增删动作；输入不展示 H0、H1、ADD/REMOVE 或候选实例标签分配。给定的三帧真实原图、目标裁剪、图像引用和完整本体仍可用。缺少明确证据不能证明不存在，null 类别也不能自动代表看不清。

Python 持有 H0/H1 的真实差异，把存在性判断映射到修改许可。A 仍要求全部修改通过才整份接纳；B 仍只应用通过且满足组件依赖的局部修改。Phase 固定为 H0。这一轮不再改变 A/B 的修改范围、依赖和失败回退规则，也不根据本轮 GT 修正规则。

这是对已观察到的接口歧义的修正，不代表文字证据已经获得独立验证。即使 enum 更清楚，视觉误判、null 定义理解或共同漏检仍可能存在。

## 共享输入的五臂对照

每个目标采用当前冻结的纯 API H0 请求：三帧因果输入（可用短历史不补帧）、当前原版提示、完整本体与五头 final-only Schema，模型 `qwen/qwen3.8-max-0902`、严格 Alibaba，temperature=0、reasoning=low、max output tokens=4096，历史图 low detail、目标图 high detail。

本轮所有阶段均使用同一 Qwen 型号和路由，避免“新旧审核同时换模型”的混淆。冻结 H0 后，盲定位和候选只各调用一次；旧审核与新审核共享 H0、候选及完全相同的原图/裁剪。新审核的输入去掉候选标签叙述，这是中性审核对象设计的一部分。

对比 H0、未经审核的候选策略、旧双假设审核结果、新 A、新 B。B 从新审核结果离线计算，不再调用模型。候选缺失、无变化或任一阶段失败的目标仍保留在总表中；另报实际候选/有效审核子集，不混淆分母。

这里的“旧审核”指已有的整份双假设审核，不是上次失败的逐项 `diff_review_v1`。本轮不额外运行 v1 第六次调用，因此可检验修正后的 A/B 相对 H0 和旧流程是否有收益，但不能单独量化“只改存在性接口”相对 v1 的因果效果。

正常路径最多 5 次 POST/目标，24 个目标总计最多 120 次；不自动重试。不同目标可并行，单目标内仍按依赖顺序运行。API 直接 HTTP 调用，保留完整本地 Schema 校验；只从供应商侧 wire Schema 去掉已证实不支持的 `uniqueItems`，不放宽本地验收。当前默认纯 H0 入口不因此改变。

## 评估与停止边界

所有新预测保存后，才关联 GT/mask 并评分。运行时仅做标签可用性检查，GT 值不进入请求、候选生成、审核或接纳决策。

固定报告内容：

- 各头 micro-F1、集合 Accuracy、TP/FP/FN、有效 GT 数量；所有有效头同时全对的数量。
- 部分减错、完整改对、改坏、等损失替换、mixed、保留数量；单个头 wrong→exact / exact→wrong。
- 候选中的有益/有害标签增删分别有多少被最终应用；以 GT membership 离线定义，每头按 mask 排除缺失 GT，分母为零时不编造百分比。
- 候选是否增加正确 IVT、审核是否只降低误改而无法补足共同漏检。
- 各阶段调用次数、失败与回退、实际费用、任何未定价调用及并行条件。

关键判断是是否改善 IVT 语义指标，以及是否付出了更多误改或其他头损伤。合法率提高、文字更长、全选 KEEP 或代码测试通过，都不作为修复成功。若未显示语义收益，保留 H0 并报告局限，不为了完成架构继续叠加模块。本轮结束后不根据这 24 个 GT 继续修改提示再报同批分数。
