# Main API Pipeline

Updated 2026-09-06. This is the main entry point for the adopted initial five-head
predictor. The old full research Pipeline remains available separately.
See the [promotion and validation record](MAIN_H0_PROMOTION_2026-09-06.md).

## Adopted protocol

| Item | Main version |
|---|---|
| Entry point | `scripts/run_dataset_api_pipeline.py` |
| Real configuration, also the CLI default | `configs/perception/joint_openrouter_h0.yaml` |
| Offline configuration | `configs/perception/joint_mock_h0.yaml` |
| Model / route | `qwen/qwen3.8-max-0902` / strict Alibaba, no provider fallback |
| Visual window | `[t-50,t-25,t]` at source 25 FPS, relative seconds `[-2,-1,0]` |
| Output clock | One target per available 1 Hz annotation point; windows overlap |
| Image detail | Historical low, current high, explicitly forwarded on the wire |
| Generation | Temperature 0, reasoning low, maximum completion 4096 tokens |
| Calls | One initial call per target; no retry, Verifier, Repair or report API call |
| Prompt | Original evaluated baseline, full ontology and full repeated JSON schema |
| Response | `joint_perception_final_only_v1`, five final label fields |

At the beginning of a video or immediately after missing source observations,
only 1 or 2 genuine available images may exist. The request records
`window_state=partial_history` and the actual count. Images are not repeated,
future frames are not substituted, and these targets are not silently discarded.

The runtime owns its prompt in
`src/surgical_agent/perception/prompts/perception_prompt_main_h0.txt` and builds
the complete system message, ontology and input JSON in
`src/surgical_agent/perception/main_h0.py`. The strict response schema is
generated by `final_only_schema()` in `src/surgical_agent/perception/final_only.py`
and is included in every prepared request and provider response-format contract.
No `artifacts/preflight` file or experimental script is required to run it.

## Prepare actual requests without API calls

Provide your own dataset path. This command reads six target windows, writes safe
request metadata and text/schema payloads, and makes **zero** provider calls.
It does not require a credential.

```powershell
python scripts/run_dataset_api_pipeline.py --mode engineering --video-id VID110 --target-frame-id 8601 --max-frames 6 --dataset-root D:/cholec_dataset --preflight --run-id h0_preflight
```

`preflight.json` reports planned calls, frame IDs, image counts and request hashes.
The `requests/` directory does not contain image bytes or credentials.
Use a new run ID for each run; an existing output directory is never overwritten.

## Real API run

Keep the API key outside Git. Substitute the dataset and credential paths.
This command schedules **six initial API calls** before cache hits. The sample
targets advance by 25 source frames, not by one raw video frame.

```powershell
python scripts/run_dataset_api_pipeline.py --mode engineering --video-id VID110 --target-frame-id 8601 --max-frames 6 --dataset-root D:/cholec_dataset --api-key-file D:/private/openrouter-key.txt --authorize-data-upload --max-provider-calls 6 --run-id h0_real
```

The upload flag is the existing CLI contract. Each live call has a provider
attempt budget; failures are recorded and terminate the run rather than being
silently retried at the expense of later targets. Reusing the cache avoids
paying again for identical requests. Preflight establishes local readiness,
not provider availability, account balance, or a guaranteed response latency.

One complete official split can be selected with `--mode paper --split validation`
or `--split testing`, omitting the per-video and maximum-frame arguments.
This selector means complete-split execution, not publication eligibility.
Do not launch the full split before estimating its sample count and spend.
The current user request only promoted the code; it did not launch a paid run.

## Result semantics

The API returns this shape; the IDs below illustrate a possible output and are
not supplied as the answer to a target frame:

```json
{
  "schema_version": "joint_perception_final_only_v1",
  "instrument": {"selected_ids": [2]},
  "verb": {"selected_ids": [2]},
  "target": {"selected_ids": [0]},
  "ivt": {"selected_ids": [60]},
  "phase": {"selected_id": 3}
}
```

Predictions, evidence, request provenance, usage and a run manifest are written
under `artifacts/api_dataset/<run-id>/`. Evaluation reads GT separately and uses
one validity mask per task. Null IVT 94–99 are valid classes. A missing IVT label
does not remove a valid Phase label from Phase's denominator.

The internal fixed-size vectors are binary selected-label indicators with
`hard_label_v1` semantics. They are not model probabilities, top-k rankings, or
calibrated confidence. The evaluator emits `frame_recognition_metrics_v2`, with
task-masked Precision/Recall/micro-F1 and exact label-set accuracy under
`label_metrics`. AP/mAP for a task containing valid `hard_label_v1` predictions
is explicitly `null` / `unsupported`, not a ranking benchmark score. A task
with no valid GT returns null label metrics and a zero valid-frame count.

## Historical versions and the research Pipeline

The current selection does not adopt `schema_only`, `tuned`, six-frame input,
five independent experts, grounded repair, or training-set visual examples.
Their experiments and frozen inputs are preserved as evidence. Several
apparently duplicated configurations are explicitly listed in preservation
manifests and are not safe to delete as unreferenced runtime clutter.

`run_final_dataset_pipeline.py` remains the explicit Tracker/Gate/Verifier
research runner with its historical top-k protocols. Its decision support
depends on ranked alternatives. Passing the new final-label H0 into it fails
early with a clear message; missing scores must not be interpreted as zero
confidence or filled with invented candidates. Adapting/retraining that Gate
is separate work, and no full-system accuracy claim follows from this H0 update.
