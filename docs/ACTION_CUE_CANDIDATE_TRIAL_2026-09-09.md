# 动作线索补候选：固定 v1.1 审核的配对测试

2026-09-09。用户授权“可以的，去试试吧”。本实验只替换补候选请求的 `instructions`，不升级默认。其余请求字段、JSON Schema、候选上限、标签边界、模型、路由、思考设置、三张图片与 detail 均固定。

## 预先冻结的比较

- `control`：当前默认补候选说明。
- `action_cue`：提示检查尖端开合、持续接触、组织相对位移与张力、液流方向，同时保留当前帧、仅补候选、不重复、不凑数、四列表 JSON 等要求。具体文本在 `src/surgical_agent/research/verification/prompts/action_cue_candidate_v1.txt`。
- 两组逐目标共用一次新 H0 和一次独立 Phase 五席判断。Phase 不受改词影响，不计为该 prompt 的收益。
- 每组各一次补候选，沿用当前 `parallel-phase-repair-v1.1.0-compact-prompt` 的五席四头审核、五份有效均分、4 分添加/2 分删除及原组件保护规则。
- 只有同一目标两组全部五席请求完全相同，才共享整组审核回答，包括失败；候选池不同则重新审核整个池，不复用部分票。
- 每个目标交替两组先后，两个目标并行；不增加修复轮数、重试、换模型、Tracker 或 Gate。

## 预设成功条件与成本

相对本轮新鲜 control：正确 Verb 候选覆盖率和最终 Verb micro-F1 均严格提高；Verb Precision、Instrument F1、Target F1、IVT F1 均不下降；无选择器异常；全部 24 目标实际尝试；24 对补候选原生输入 Token 都可核实且均不增加。候选覆盖增加本身不算修复成功；共享 Phase 不作为 prompt 优势。无论结果好坏，不因评分修改本轮模板、阈值或样本。

准备阶段对完整补候选消息文本检查 UTF-8 字节及 cl100k/o200k 两套参考分词不增加。它们不是 Gemini 官方计数；最终检查提供方原生 usage。即使补候选文本变短，候选池改变仍可能增加后续审核输入/输出，因此整条流程成本单独报告。

最多 432 次推理请求：24 ×（共享 H0 1 + 共享 Phase 5 + 两组各补候选 1/审核 5）。同池共享或失败会减少调用。累计硬上限 OpenRouter $4、xAI $3、阿里云 ¥2；按原生费用、人民币估算及未知预留分别记账，不把预留当实付。原生响应封存后离线重放，关闭推理后才读取查询 GT 评分，失败目标保留在分母中。

入口：`scripts/run_action_cue_candidate_trial.py prepare/execute/score`。所有输出进入新的单次使用目录；默认管线、历史代码与成绩不被覆盖。

## 准备检查与归档

模板 15 项、调度/共享 5 项、评分 15 项测试通过；原默认精简管线的 15 项回归检查通过。真实请求结构的离线合成档案另验证了：同池及失败席完整共享（13 条合成请求）、不同池重新运行五席（18 条合成请求）、Gemini rows 适配、Phase 合并及全部原响应逐字重放。该检查禁止 HTTP POST，没有实际 API 请求。证据 `artifacts/research/action_cue_offline_replay_20260909/summary.json`。

首次 prepare 的 v1 目录因源文件发现误纳入动态模块的虚拟 `__file__` 而中止，发生在任何推理之前，付费调用为 0。修复为只纳入真实存在的模块文件，明确指定的必要源码仍强制存在；没有改变 prompt、样本或模型。

实际推理目录：`artifacts/preflight/action_cue_candidate_20260909_v2/`。冻结 plan SHA256：`b16f2beee6c23d96b6c47361c907d793e733a4ca9106823c31d578b62048b041`。每目标 H0 和 Phase 请求指纹在推理前冻结；依赖 H0/补候选回答的请求则用冻结 builder 构造并在派发前封存。首次本地异常会立即停止派发、取消排队任务，已发送请求完成后归档，不重复发送。

## 结果：未通过预设标准，保持当前默认

24 个目标全部完成，H0 全部合法；377 次实际请求及全部原始回答离线重放通过，评分后再次检查冻结快照，独立集合计数一致。两组都使用 v1.1 compact 审核；本表只能在本轮同样本内比较，不能与此前 8 个旧目标的绝对分数比较。

| 指标（%） | control | action_cue | 变化（百分点） |
|---|---:|---:|---:|
| Instrument F1 | 87.32 | 88.89 | +1.57 |
| Verb Precision | 55.81 | 58.97 | +3.16 |
| Verb Recall | 61.54 | 58.97 | -2.56 |
| Verb F1 | 58.54 | 58.97 | +0.44 |
| Target F1 | 54.29 | 50.75 | -3.54 |
| IVT F1 | 29.63 | 30.38 | +0.75 |
| Phase | 83.33 | 83.33 | 0（共用相同分支） |
| 正确 Verb 候选覆盖率 | 71.79 | 69.23 | -2.56 |

Verb TP/FP/FN 从 **24/19/15 → 23/16/16**。两组最终 Verb 不同的只有 4 个目标，均是新组比 control 少一个 `grasp`：其中 3 个是少报错误 grasp、1 个漏掉正确 grasp；其他 Verb 的最终预测与分类计数全部相同。不能把 +0.44 个百分点解释为找到更多正确动作。

独立逐帧核验确认，这 4 帧的 control 都有 grasp 候选且五票有效，新组均未提出 grasp，因此对应差异由候选缺失直接解释，并非该候选审核校验失败。`VID103_23251` 的 GT/H0 均只含 retract，control 补入 grasp 并以均分 4.6 接受，新组不补该候选而保留正确 Verb；`VID96_13326` 的 GT 为 grasp/dissect，H0 为 retract/dissect，control 补入 grasp 并以均分 4.0 接受，新组未提出它而丢掉真实动作。这里只描述标签和程序链路，不据此声称已目视核实医学动作。独立证据：`artifacts/research/action_cue_result_diagnostic_20260909.json`。

IVT TP 都为 12，FP 从 30 降到 28；Target TP 从 19 降到 17，FP 从 18 降到 17。五头合计修正 7 个标签错误、引入 3 个，错误事件数 140→136；1 帧五头全对、3 帧部分改善、1 帧有改善也有退步、2 帧变差、17 帧不变。五头全对数 control 1/24、新组 2/24；共享 H0 本来也是 2/24，这不能单独替代任务指标。

这是按目标累计的标签出现项，不是独立器械实例。新组仍有 12/16 个最终 Verb 漏报不在候选池；IVT 则有 23/27 个漏报不在候选池。新模板未改善本次要验证的候选漏报瓶颈。

369 次直接 JSON 解析成功，2 次按原规则移除完整 Markdown 围栏后解析成功，6 次 API 失败全部是共享 GPT Phase HTTP 403，两组同样回退。实际四头审核没有 HTTP 失败，但原语义校验仍会拒绝不合规评分：control 895 条候选判断中 8 条无效（Qwen 7、GPT 1），新组 810 条中 2 条无效（Qwen 2）。候选池不同会改变审核上下文和判断，不能将每一条分数变化都归因于前面的动作提示。

两组各有 1 个合法空候选池目标 VID96_17751，按原规则不调用四头审核；9 个非空目标的两组整池请求相同并共享回答。因此实际请求为 H0 24 + 提案 48 + Phase 120 + 四头审核 185 = **377**，无重试、换样或额外轮次。
