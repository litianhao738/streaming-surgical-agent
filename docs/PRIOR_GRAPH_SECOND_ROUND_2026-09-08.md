# 最新图谱版的第二轮观察反馈续测

日期：2026-09-08。状态：真实 API 续测、独立评分和请求重放已完成。

**结论：第二轮观察反馈在这批8目标上没有产生新增语义收益，最终答案与图谱第一轮逐目标完全相同。继续保留一轮图谱研究版，第二轮不升为默认方案。** 仅问题清单的第二轮多加了一个错误 Target；但该目标在观察反馈臂遇到 DeepSeek 429，不能把两臂分差归因于观察反馈成功防错。

本次是已分析 Training 目标的同批续测，不是独立确认实验；不涉及完整 Tracker／Gate 运行时间，也不改动纯 H0 默认入口。调用前协议另存于实验目录的 `protocol_before_results.md`。

## 实际比较与顺序

| 输出 | 来源 |
|---|---|
| H0 | 原八目标归档 |
| control_r1 | 原无图谱一轮归档 |
| graph_r1 | 原图谱一轮归档 |
| evidence_feedback | 从 graph_r1 续跑一轮，候选模型收到具体审核观察 |
| issues_only | 从同一 graph_r1 续跑一轮，仅收到原问题清单 |

按用户要求，先跑完观察反馈臂，再跑问题清单臂。两臂全部封账后才统一读取 GT 算分。此顺序没有交替随机化，结果仍可能受模型调用波动和提供商时间变化影响；不能把单次分差当成稳定因果效应。

每臂的候选模型都收到相同的 graph_r1 当前预测、候选池、未解决问题、原始图谱提示和原三张图片。唯一处理差异是在提案文本中加入 `review_evidence_feedback`。这些观察可能有错，不是真值，也不允许模型直接改写最终结果。图谱提示仍来自原来排除整个查询视频的 Training 统计，不重新检索或读取查询 GT。

五席只看原图片与当前完整候选池，不看反馈包、图谱频率或其他席的回答。保持原逐项规范化与均分规则；新 IVT 自身及其必要组件均须通过。单独 I/V/T 可按各自证据处理，Phase 不改。

## 第二轮停止与复用规则

1. 原图谱第一轮的7个 `UNRESOLVED` 目标有第二轮机会；1个 `MODEL_PASS` 目标直接保留。`MODEL_PASS` 不等于 GT 正确，也不能发现池外遗漏。
2. 每个 eligible 目标先请求一次候选。若候选池没有变化，标 `NO_NEW_CANDIDATES`，直接保留第一轮，不重复请求五席。
3. 候选池有变化才再完整审核一次；不拼接前后两轮的单项评分。两臂在同一目标的五份完整审核请求都相同时，共享原回答，包括失败；不为某一臂补抽结果。
4. 提案失败、审核派发不完整或输出选择违反 Schema 时保留第一轮，并记录失败状态。失败目标仍参与所有 GT 可用任务的评分。
5. 不使用本批 GT 决定是否续跑、改阈值、选提示或再追加第三轮。已高分误通过的标签可能不在反馈问题清单内，这一共同审核局限不会自动消失。

## 调用、预算与指标

观察反馈臂最多42次新增 POST；两个第二轮臂合计最多84次。每个进入第二轮的目标最多1次 Gemini 提案＋5次并行审核。没有新增 H0 请求，也不训练任何模型。

新实验独立费用上限：OpenRouter $2、xAI $2、阿里云 ¥2。原八目标费用不重复计入增量账本。OpenRouter 在执行前检查路由、价格及余额；xAI／阿里云沿用冻结保守 token 费率，实际费用、估算费用与未知费用预留分开报告。没有自动重试。

封账后，统一对五种输出计算各头 micro-Precision／Recall／F1、集合 Accuracy、TP／FP／FN和有效 GT 数；缺失 GT 按任务 mask 排除。逐目标报告全部改对、部分改善、混合损益、改坏、无收益替换和未变化，汇总修正／新增标签错误及总 FP+FN。

比较重点是 graph_r1→各第二轮、issues_only→evidence_feedback，同时保留各臂相对同批 H0 的结果。另报告候选覆盖、第二轮提案次数、池扩展数、实际五席复核数、原早停、无新增停止、失败回退、新增费用与耗时；共享面板不冒充独立计时。

## 没有改善的具体机制

1. **第二轮没有补出新的正确 IVT。** 两臂各增加4个 IVT 候选，均不符合对应 GT。图谱第一轮已经覆盖7/15个 GT IVT，两种第二轮仍是7/15；最终均选中6个，另1个在池内未选中，8个仍完全不在候选池。候选池由22项扩大至26项，错误 IVT 候选由15项增至19项。
2. **补出正确组件不等于补出正确三元组。** 观察反馈臂的 Target 池由10/15提高至11/15，Verb池仍10/14；问题清单臂的 Target池也是11/15、Verb池11/14。但最终 Target 真阳性仍8个、Verb仍10个。两臂均没有新增正确完整 IVT。
3. **审核有输出，并不意味着每项评分都有效。** 42次请求得到可解析 JSON，但多份低分判断声明只有 `LOCAL_REGION` 证据。现有规范化规则以 `LOCAL_ABSENCE_CANNOT_DELETE_FRAME_LABEL` 拒绝用局部未见来否定整帧存在性；另有评分与 finding 不一致。任一席单项无效就不计算该项均分。这些属于证据范围／回答一致性约束，不应笼统写成 JSON 解析失败。6个面板共有365个“席位×命题”条目：42条局部低分否定无效、1条 `VISIBLE_ONLY` 却给4分、23条因两次429整席缺失而无效。正常 HTTP 返回的4个面板中，也有23/50个命题无法计算均分；全部6个面板为46/73。没有发现缺ID、缺字段或超1000字符导致这批失效。
4. **循环的触发范围有限。** 每臂4个目标未扩大候选池，直接停止；1个继承第一轮模型通过。已有高分误报未必进入反馈清单；就算重新审核，旧标签降至“不确定”也不会自动删除。本次新增候选最终都没有被接纳；问题清单臂增加的错误 Target 来自旧候选重新评分。
5. **接口失败限制了对照解释。** 两次429分别影响观察反馈臂 `VID23_28876`、问题清单臂 `VID23_13176`。缺席不是1分、不是反对票；所有涉及缺席的均分为空并保留现有标签。没有删掉这些目标重算结果，也没有在看到 GT 后重试以选结果。

关键代码是 `semantic_coordinator.py` 的 `item_error`（低分必须为整帧范围）、`review_normalization.py` 的逐项规范化（剔除无效项）和 `recent_mean_panel.py` 的 `aggregate`（任一席无效即均分为空）。局部未见不能否定整帧存在的保护原则合理，但对所有候选，包括尚未选入的新增候选，都要求五席合格会造成停滞。这不是已证实的普通 JSON 解析 bug，也不能通过自动把 `LOCAL_REGION` 改成 `WHOLE_FRAME` 来解决。

以上能确认“这一次续测没有新增收益”。不能确认所有第二轮都无效，也不能把问题全部归于模型能力、图谱、限流或单一校验规则。下一步若继续研究，应先离线区分“拒绝新增”和“删除已有标签”对反证范围的不同需求，并复核误报为何能获高分；不直接放宽五席有效性或再加第三轮。本轮没有执行这种后续变体。
