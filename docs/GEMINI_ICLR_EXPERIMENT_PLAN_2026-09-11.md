## 1. 初稿实际要求

初稿的三项贡献为 Selective Verification（SV，选择性验证）、Evidence-Grounded Repair（EGR，基于证据的局部修复）、Reliability-Aware Memory（RAM，可靠性记忆）。它不只是“用 Gemini 跑几个消融版本”，还要求证明何时值得审核、审核是否误改、历史错误是否持续传播。

PDF 第 5–7 页给出六张表，Table 2 明确以 Qwen3.8-Max-0902 为共同基座。用户现在选择 Gemini，应将 Table 2–6 的共同基座统一为 Gemini 3.8 Flash，重新测量各表数值，不能只替换模型名称。Table 1 保留跨基座比较。

数值来源尚未确认：例如初稿 Grok IVT=31.70、Qwen IVT=34.00，而导入完整 Testing 的 H0 指标分别为 37.19 和 27.64。这可能涉及示例值或协议差异，不能认定初稿数值来自当前项目。所有未追溯到原始记录的数字均标为待实测，不据其设定目标收益。初稿里的 GPT 排名也不是本项目选型证据。

建议的基本配置共 11 种：H0、Full、Verify All、Confidence、Rule、Random、All-task Rewrite、Flagged-field Re-query、No Memory、Uniform Memory、Verified-only Memory。

这不是“只跑 11 遍就齐活”的承诺：预算点、随机重复、数据集及独立闭环轨迹还会增加运行数。只有定义完全一致时，w/o SV 才复用 Verify All；w/o EGR 可定义为 All-task Rewrite；w/o RAM 可定义为 No Memory。Confidence 与 Uncertainty-only 只有分数定义一致才共享。初稿 Table 2 的 Verify All 与 Table 3 的 w/o SV 数值不同，正式实验需明确是否存在其他配置差异；若无差异应来自同一实验记录。

除了六表，建议两张图：质量–实际费用 Pareto 曲线；沿连续视频展示 H0 错误、审核/修改、写入状态和后续传播的时间线。无需为了凑图重复调用 API。

## 4. 推荐实施顺序

1. **冻结论文实验协议。** 明确最终 Full 的功能、Gate 是二元调用决策还是三 scope 路由、RAM 是否影响 H0、T0/T1 是否纳入主论文。先保存实验配置和评分定义；第二个数据集目前仍未指定，不能承诺双数据集结论。
2. **先做 Gemini 连续片段集成验证。** 检查帧顺序、记忆跨视频清空、Pending 复查时间、无未来帧和 GT 入特征。仅离线单元检查不足以证明真实闭环；正式采集前用预设短片段估算费用。
3. **采 Training 四视频的反事实样本。** 对同一调用前快照同时保存 H0 与审核结果，包括改好、改坏、无变化和请求失败。Gate 特征在审核前冻结，GT 只用于离线标签。不得只收集高风险或成功修复样本。
4. **训练、验证和预算校准。** 按视频划分/交叉拟合 Gate；先验、标准化、校准和阈值都不能看留出标签。现有三 scope trainer 需要各 scope 的独立结果和 paired T0/T1；若改成二元 Gate，需新增明确版本，不将缺失 scope 自动标成负例。若沿用该 trainer，还要完成其要求的 cross-fitted D1，而非只交付 bootstrap G0。
5. **冻结最终系统后跑正式评估。** 主结果和 Table 2/3/6 按各自策略因果闭环运行。Table 4/5 可增加共享状态的诊断实验，但不能把共享快照重放冒充记忆分布会变化的真实部署结果。
6. **跨基座验证和第二数据集。** 优先复用已有 Grok/Qwen H0，核查图像内容、采样、提示、掩码、模型版本和解析协议。统计先验不能由 Testing 真值建立。传统 surgical VLP 基线需同协议实测或清楚注明不可比的文献值。

### 特别重要的反事实边界

对同一个状态 x，可以比较 H0 与一次审核的局部收益；但当门控/记忆改变历史时，后续状态 x 也会变。旧 Verify All 轨迹的结果不能无条件当作新 Gate/RAM 轨迹的反事实结果。

只有请求正文、图片、模型、上下文快照和生成参数完全相同的调用才可跨臂缓存复用。RAM 影响 H0 时，各臂 H0 也不再必然相同。Pending 在未来 t+k 得到解决，不能回填为 t 时刻已知的在线正确输出；如报告延迟修正，须独立列出延迟指标并计入复查费用。

## 5. 评分协议待冻结项与建议定义

- **五任务 F1**：建议先维持项目 task-level micro-F1，按各任务有效掩码累计 TP/FP/FN，五头等权平均。Phase 同时单列 accuracy，避免缺失预测时将其与 F1 混用。若投稿领域要求 macro-F1/mAP，应并列真实实现，不从硬标签 F1 换名。
- **分母与失败**：预定全部目标纳入端到端结果；失败率和成功子集诊断另列。15,282 是现有 Testing 推理位置数，导入基线 IVT 有效帧只有 7,061；逐任务写清支持数。
- **Frame Verify Rate**：唯一触发二阶段审核的目标数 / 全部预定目标数；独立报告审核 API 总请求、失败/重试、Pending 复查。不把五个审核席算成五帧。
- **Error Recall**：H0 至少一个有效任务字段错误且被选中审核的帧 / H0 错误帧。必须在调用前选帧，不能用 GT 选帧。
- **BVR**：建议采用审核事件/帧为单位，预先定义逐样本损失下降才算改善；若继续按 API 调用口径，必须说明五席面板的联合收益如何分配。它不是简单的“选中错误帧比例”。
- **收益监督**：可先定义有效任务上的等权标签集合损失差 ΔL=L(H0,GT)-L(repaired,GT)，把实测费用/时延作为独立变量；只有最终采用并实现 E[ΔL|x]-λE[cost|x] 时才声称收益–成本 Gate。现有二分类逻辑回归的收益概率不自动等于该期望效用。
- **Correction Recall / Harm / Repair Precision**：冻结调用前 flagged 集；以字段为单位定义正确集合、错误集合、改好及改坏。Harm 主指标建议用被审核帧中所有原本正确字段作分母，并额外列“未标记但被误改”事件，避免全任务重写的越界错误被排除。所有臂使用相同分母规则，区别标签级增删统计。
- **MCR**：建议主指标统计首次写入长期记忆时的错误条目数 / 首次写入条目总数，GT 只用于离线核查。另报覆盖率与驻留错误比例；No Memory 标 N/A，不能用 0 伪装最优。verified 是系统状态，不等于 GT 正确。
- **EPR@5**：初稿定义还不够精确。需明确“连续五个评估帧仍错”还是“第五帧仍错”、如何追踪同一错误、标签真值切换如何处理、视频尾和缺失掩码如何排除。建议主表采用同任务同标签错误在后续五个连续有效评估时点持续存在的比例，注明标签有效性/真值切换条件；另报普通任务错误持续率。不能拿三个稀疏样本估计。
- **不确定性**：Gate 不得用审核后的五席分数做调用前特征；Gemini 当前 H0 是否提供可校准置信度需另行验证，不能把标签 ID 或事后正确性当 confidence。
- **统计和预算**：报告逐视频结果与视频级配对差值；置信区间按视频/时间块而非独立帧处理。匹配审核帧数不等于匹配费用，Table 4 同时列实际 tokens/美元及局部动作类型。流式门控不可利用未来帧全局排序；离线 top-k 只能标成离线诊断。

## 6. 已有数据能填哪些位置

Grok/Qwen 的完整 H0 可以在协议核验后填 Table 1 对应 baseline 行，不能推出 Ours、Gate 或 Memory 指标。六样本及新增三样本 Gemini/Sol/GPT-6 仅为开发选型证据，不填完整测试集主表。已使用过的 Testing 小子集应记录为开发暴露，后续结果需披露，不能称整个 Testing 从未见过。

当前主线原始响应可做局部修改收益/伤害审计，也可重放其三条既有预测臂；这些记录没有自动包含 RAM 反事实、独立 scope 或 T0/T1，因此不能直接宣称全套 Gate 训练数据就绪。

对保持固定 12 次二阶段审核且无额外步骤的无状态二元 Gate，调用参考公式为 N×(1+12r)，r 为验证帧比例。r=0.35 时为 5.2N 次，比 13N 少 60%，但**费用不会必然减少 60%**，因为模型与 tokens 单价不同。初稿 34.6% 不能当作已实现验证率。

全套费用应在短片段集成试验后，用每个唯一请求的实测成本、每臂实际闭环长度、预算点、随机种子、D1/T0/T1/scope 数重新估算。不能把 11 个配置直接乘以单遍费用，也不能承诺“一次全审核后所有表零成本重放”。
