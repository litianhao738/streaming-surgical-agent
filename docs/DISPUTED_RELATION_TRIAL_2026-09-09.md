# 争议关系一次视觉复核：独立新目标实验

日期：2026-09-09。目的：检验新增 Verb 的严格门槛导致 IVT 连带误挡时，一次视觉复核能否同时保住 Verb 与 IVT 的语义指标。默认 Pipeline、历史最佳结果和旧实验均保留。

## 预先固定的协议

三种修复版本共享全新 H0、图谱补候选和原五模型回答：原五席均分规则、五席全部支持新 Verb 的严格规则、严格结果＋争议关系复核。另列共同 H0。H0／提案／额外复核使用 OpenRouter `google/gemini-3.8-flash`，固定 Google AI Studio；五席仍是原 Grok/Qwen/GPT/Gemini/DeepSeek。Phase 全部沿用 H0，本轮没有独立 Phase 审核、Tracker、Gate 或扩候选。

仅当原规则已经接纳一个新增 IVT，而严格规则仅因新 Verb 的有效 `UNCLEAR=3` 票阻止它，才考虑复核。该 IVT 和三个组件都必须有五份有效审核、均分 ≥4，且不得存在任何有效 1–2 分反证。无效票不能当“不确定”进入这条路径。

每帧将全部符合条件的既有关系打包，最多调用一次现有 Gemini。它只看原始三张因果图、待核关系及既有类别边界，不看 H0 答案、五家票数/均分、审核文字、图谱先验或 GT。输出绑定关系 ID 的 SUPPORT／REFUTE／UNCLEAR、图片引用和短英文观察（最长 1000 字符）。SUPPORT 必须引用目标图，才能把该 IVT 及必要组件成组加回严格结果；其他情况或失败保留严格结果。不会因为一个关系被拒就删除整帧动作，不重建全帧 I/V/T，不改五家的原始分数。

## 具体失败原因

**1. 额外看图仍能确认一个错误动作，规则没有提供语义真值。** `VID31_78851` 是唯一触发目标。原规则新增 `grasp`（Verb 0）和 `grasper/grasp/gallbladder`（IVT 7）；对应五席评分分别为 `[3,5,3,5,5]`、`[3,4,3,5,5]`，均分为 4.2、4.0，所有相关票均有效。严格规则挡住两项，额外 Gemini 却引用全部三图，以器械夹住、保持胆囊为理由返回 SUPPORT，于是 Python 按设计把两项加回。

该帧 GT 含 `grasper/retract/gallbladder`（IVT 17），没有 `grasp` 或 IVT 7。对照标注，新复核增加 1 个 Verb 假阳性和 1 个 IVT 假阳性。原始回答重放与成组接纳一致，没有发现这里发生 ID 错配、字段丢失或意外全头重建。能够确认的是模型判断与标注语义不符；“握住”是否足以额外标注 `grasp`，不能靠合法 JSON 或一段视觉解释来证明。此处也没有 429、无效票或解析失败来解释误加。同一 Gemini 再调用一次，依然可能重复提案模型的误认。

**2. 触发范围太窄，正确的独立 Verb 没被救回。** `VID96_12701` 的 GT 是 Verb 0、IVT 7。原规则依据 `[4,5,3,5,5]`、均分 4.4 新增了正确 Verb 0，严格规则因一票 UNCLEAR 将其挡住。正确 IVT 7 实际已经在候选池里，并非此次漏候选；但它的五席分数为 `[4,4,1,5,5]`，均分只有 3.8，原规则就未接纳，所以没有进入“原规则已接纳、仅被严格 Verb 阻止”的复核入口。新方案最终也没恢复这个正确 Verb。

GPT 给 IVT 的文字是没有清楚看见足以确认关系的器械，却填了 WHOLE_FRAME/REFUTED/1；其格式可以通过校验，文字所表达的不确定性是否足以构成否定仍需语义判断。这显示“声明看了全帧”不等于已经证明不存在。当前协议仅处理有效 UNCLEAR 导致的连带阻止，不能覆盖关系本身的错误反驳或低分。

**3. 更普遍的候选缺口没有被本方案处理。** 24 帧 GT 共 40 个 IVT 出现项，原候选池只覆盖 18 个（45%），另 22 个不在池内；池中还有 52 个错误 IVT 出现项。最终各版只保留 8 个正确 IVT。既有漏候选，也有候选出现后未选中和错误关系被保留的问题。这个只恢复已被原规则接纳关系的方案无法扩大覆盖；不能用一次复核解决全部问题。

以上是本批的可追溯诊断，不据这两帧写特判，也不把全部低分归因于单一模型或单一代码规则。新目标来自曾使用过的四个 Training 视频，仅一个额外复核触发，不能据此估计该复核的总体准确率。

## 调用、失败、费用与时间

实际 164 次同步 POST：24 次 H0、24 次提案、115 次审核、1 次额外复核。目标顺序运行，每目标五席审核并行。`VID103_41351` 的 H0/候选池为空，跳过五席审核并保留 H0，仍纳入全部 24 目标评分。

固定五席：Grok `grok-4.6`、Qwen `qwen3.8-flash`、GPT `openai/gpt-5.6-luna`、Gemini `google/gemini-3.5-flash-lite`、DeepSeek `deepseek/deepseek-v4-flash-vision-exp`。H0/提案/额外复核均为 `google/gemini-3.8-flash`。Grok 和 Qwen 沿用原直连接口，其余走 OpenRouter 固定路由；并非五席全改用 OpenRouter。

160 次 JSON 解析成功，3 次 DeepSeek 上游 429（`VID103_17126`、`VID103_23751`、`VID96_7951`），1 次 Gemini 审核 HTTP 200 但安全 JSON 解析拒绝（`VID31_21801`）。没有自动重试或换样，失败回答不能变成有效票。23 个审核面板共有 210 个候选命题，其中 136 个获五份有效意见，74 个存在缺票或无效意见。这里的有效性还包括局部否定不足、分数/判断矛盾等检查，不能把所有无效票都称为接口失败。选择器异常为 0。
