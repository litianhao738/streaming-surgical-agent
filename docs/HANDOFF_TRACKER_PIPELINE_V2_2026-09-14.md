# 交接：Tracker 流水线 v2（2026-09-14）

## 0. 结论

在**不改当前默认**的前提下，新增一个独立研究版本 v2，改动如下：

- Tracker 在出口直接修正器械；
- 单功能器械确定动作；
- 因果阶段滤波；
- 只审交互项；
- 重新训练 Gate v2。

在 6,059 条 Training 首轮行上，按视频嵌套留出评估：

| 指标 | 当前默认 PGP | v2 |
|---|---:|---:|
| 五头平均 F1 | 61.70 | **66.11** |
| FP+FN | 36,150 | **32,598** |
| 逻辑调用 | 37,157 | **24,047** |
| 估算美元 | 86.41 | **约 56.0** |

- 4 个视频的 F1 和错漏都有改善。
- 与"每帧都审交互"相比，Gate v2 保留了 **93.4% 的 F1 收益**和 **90.9% 的错漏减少**，达到事先定的 90% 目标。当前默认的保留率为 83.66%。

以上都是零 API 的离线结论，数据只有 4 个反复用于开发的视频，替换默认之前必须做独立验证。

## 2. v2 流程

```
① 三帧因果输入（当前帧及前两秒）
② H0（Gemini 3.8 Flash）五头初稿 ………………………………… 1 次调用
③ proposal + 先验接纳 → 便宜答案 ……………………………………… 1 次调用
④ Qwen compact 初审（1 次调用）+ Gate v2（HGB，42 维）
     ├─ 跳过（约 70%）：便宜答案
     └─ 放行（约 30%）：其余 compact 审核员依次审交互四头
          精确早停 + 首轮 fallback + grasp/retract 回滚；不跑阶段分支
⑤ 出口后处理（本地，零 API，按此顺序）
     M1 Tracker 融合：instrument := Tracker 集合；删除器械不在集合中的 IVT
     M2 单功能器械定动作：clipper→clip，hook→dissect，scissors→cut
     M3 因果阶段滤波：当前及过去 W 秒输出阶段的众数
⑥ 五头输出
```

每帧平均约 4.0 次调用，约 $0.009。

## 3. 模块实现要求

### M1 Tracker 出口融合
- **来源：** 冻结的 `artifacts/training/tracker_clip_v2_oof5_20260906`，不重新训练。
  - Training 视频用 `oof/index.json` 对应的留出预测。
  - VID110 和 Testing 需要用 `full/checkpoint.pt` 在本地做因果推理，现在还没有这些视频的预测文件。
- **规则：**
  - 取当前帧 score ≥ 0.35 的器械集合。存储的检测似乎已按 0.35 过滤过：0.25 的结果完全相同，0.5 几乎相同。
  - 令 instrument 等于这个集合，并删除器械不在集合中的 IVT。
  - verb、target、phase 不改。
  - 这一帧没有 Tracker 输出时，保留原答案并记录。
- **位置：** 放在审核和歧义回滚**之后**。不要前移到便宜档之前，因为那样会改变审核员看到的输入，现有缓存就无法验证了。
- **依据：** 审核员改过器械的 101 帧里，便宜档有 104 个器械错误，审核后 102 个，Tracker 只有 31 个。所以器械以 Tracker 为准。
- **注意：** specimen_bag（instrument 6）没有对应的 IVT，按上面的规则处理即可。

### M2 单功能器械定动作
- **规则来源：** 在 Training GT 上统计 P(帧中有该动作 | 帧中有该器械)。条件是概率 ≥ 0.8、样本 ≥ 20，并排除 grasp/retract。4 个留一视频折得到的规则完全一致：clipper→clip、hook→dissect、scissors→cut。**冻结这三条。**
- **应用方式：** 放在 M1 之后，用融合后的器械集合，只往 verb 头里加，不改 IVT 和 target。
- **说明：** 排除 grasp/retract 是看到结果之后决定的，依据是之前发现的标注习惯分裂（见 `HANDOFF_GATE_OFFICIAL_DATA_FIXES_2026-09-13.md`）。把 grasp 和 retract 合并成一类计算，动作 F1 仍从 71.95 升到 75.51，说明不是标注习惯带来的假提升。这条仍需要在独立视频上验证。

### M3 因果阶段滤波
- **规则：** 输出阶段取当前帧及过去 W 秒内输出阶段的众数，平局时保留当前阶段。滤波只作用于便宜档的阶段，阶段不送审。
- **部署：** 在 1 fps 的输出流上滚动计算。训练行有缺口，线上的输出会更密。
- **窗口选择：**
  - 从事先定的网格 {5, 10, 20, 30, 60} 秒中按视频嵌套选：3 折选了 60 秒，VID31 选了 30 秒；阶段 F1 从 73.46 升到 **83.96**。
  - 在 4 个视频上用留一评估，60 秒最好（85.23）。**建议冻结为 60 秒。**
- **不采用的两种：**
  - HMM 前向滤波（82.36）不如简单的窗口；
  - 把网格扩到 180 秒后，嵌套结果反而降到 83.28，说明窗口选择不稳定。
- **必须报告阶段切换延迟：** 滤波会让阶段切换晚大约半个窗口才被识别出来。

### M4 只审交互
- **执行：** Gate 放行时用 action = 1，只跑 compact 四头分支，跳过 phase recommendation 和 joint 阶段审核。
  - `src/surgical_agent/research/gate/pgp_gate.py` 的 `compose_output` 已支持位掩码；
  - 需要在 `src/surgical_agent/research/gate/pgp_runtime.py` 的路由里支持 action 1。
- **不变的部分：** 精确早停、首轮 fallback、歧义回滚。
- **成本公式：** 放行帧 3 + max(kc−1, 0) 次调用，跳过帧 3 次（H0、proposal、Qwen）。这个公式在 6,059 行上与记录的成本逐行一致。

### M5 Gate v2 重训
- **标签（不需要 GT）：** 对 M1+M2 修正后的交互四头，判断"审核后 ≠ 便宜档"。正例率 6.54%，共 396 帧。
- **特征与模型：** 与默认相同的 42 维（32 维便宜档特征 + 10 维 Qwen 特征）。HGB 参数：`max_iter=200, learning_rate=0.05, max_leaf_nodes=15`，按正负样本平衡加权，`random_state=3407`。
- **门槛：**
  - 嵌套留一视频；候选审核比例从 5% 到 100%，步长 5%；
  - 取满足下面三条中最便宜的一个：F1 增益 ≥ 90% ×（每帧都审 − 不审）、错漏 ≤ 不审、每个内层视频都不差于不审；
  - 然后在 4 个视频上全量拟合，用同样方法定最终门槛。
- **预期外层结果：**
  - 审核 1,810 帧（29.9%），24,047 次调用，约 $56.0；
  - F1 收益保留 93.4%，错漏减少保留 90.9%，捕获了 90.9% 会被审核改动的帧；
  - 留一 AUC 0.897。
- **对照：**
  - 不用 Qwen 的 43 维版本：AUC 0.738，保留 95.2% / 95.6%，但调用 28,020 次、约 $65.3，不选；
  - 旧默认路由直接用于只审交互：26,647 次调用、约 $60.5，保留 93.8% / 92.1%，作为对照。

## 5. Gate 的论文证据（成本–保真）

同样的审核比例下，按"捕获会被审核改动的帧的比例 / F1 / 调用次数"比较（阶段滤波固定 10 秒）：

| 审核比例 | 学习 Gate（含 Qwen） | 学习 Gate（无 Qwen） | 随机（50 次平均） |
|---:|---|---|---|
| 10% | 53.3% / 65.32 / 20,315 | 26.3% / 65.25 / 10,926 | 10.1% / 65.19 / 10,549 |
| 20% | 81.1% / 65.36 / 22,277 | 44.4% / 65.29 / 13,648 | 20.3% / 65.21 / 13,025 |
| 30% | 92.4% / 65.39 / 24,053 | 60.4% / 65.33 / 16,312 | 29.8% / 65.23 / 15,496 |
| 50% | 97.5% / 65.39 / 27,062 | 83.1% / 65.37 / 21,549 | 50.3% / 65.28 / 20,452 |
| 70% | 99.2% / 65.40 / 29,725 | 96.7% / 65.39 / 26,502 | 70.1% / 65.33 / 25,409 |

需要如实说明的三点：

- **按"相同调用次数"比较，优势会小很多**，因为 Qwen 初审每帧都要付费。例如都在约 2 万次调用时，学习 Gate 的 F1 是 65.32，随机是 65.28。论文要同时画"按审核比例"和"按实际花费"两种横轴。
- **审核带来的准确率提升很小。** 不审核是 65.89，v2 是 66.11，每帧都审是 66.12。Gate 应定位为成本–保真控制器：用每帧都审 73% 的调用，拿到 93% 的收益。
- **学习 Gate 的优势主要体现在保真度上。** 同样审核比例下它的 F1 也高于随机，但提升的绝对值很小。
