# 有限历史补图：与同图追加审核的 Training 对照

本协议在名称和严格独立核验的 Training 结果已经可见后提出，属于开发期追加实验。它不使用 Validation / Testing 的标签或成绩，不声称最初就预注册，也不修改冻结 H0。名称 B 的有效 IVT 判断有 14 条 UNCLEAR；严格独立核验 B 的 IVT F1 为 40.00%，低于 H0 44.44%。把超长说明统一缩短到 1000 的零调用补充分析仍没有改变该结论。当前证据不足以把不确定全部归因为图片不足，本试验只检验新增真实历史画面是否有用。

## 唯一主要对照变量

固定已完成的 `verifier_goal_training_collect_20260907` 与 `verifier_goal_training_named_pair_20260907`：同一 H0、盲定位、H1、原图、裁剪和首次 names 审核。整个试验始终保留原 16 个 Training 目标；I/P 有效 GT 16，V/T/IVT 有效 GT 15。GT mask 只参与评分，不控制补充审核触发。

只在首次有效 names 审核有 Verb 或 IVT 的 UNCLEAR，且候选有变化、存在额外真实历史图时触发。实际为 9 个目标；按行为计数是 15 条 IVT、1 条 Verb 的 UNCLEAR，其中一条 IVT 无 GT，不能拿可评分的 14 条作为实际触发总数。

两臂均最多追加一次整份审核，不展示首次回答、H0/H1 身份、增删方向或 GT：

- `repeat1000`：实际 wire 与首次 names 请求完全一致，作为“原图多问一次”的对照。
- `memory1000`：只前置最多两张真实过去图像（low detail），及与它们直接相关的帧号、时间、图片引用和位置。它们在原始帧号上为 t-100、t-75，即 -4、-3 秒；原 -2、-1、0 秒和目标裁剪不变。系统说明、本体、命题、Schema、生成参数和目标全图引用均不变。

向过去扩展时逐个检查 t-75、t-100，遇缺帧即停止，不跨缺口取更老图、不重复或合成帧、不取未来图。不同视频不共享内容。不存储过去预测作为真值，也没有跨窗口文本记忆、检索库、Tracker 输入或自由反思循环。这里只是一次条件触发的有限历史补图。

两臂的执行先后按目标轮换。第二次审核有效时整份替换首次 review；失败、非法或未派发时，两臂均复用首次有效 review。未触发、无额外图、候选不可用或无变化的目标也保留并明确标记。不得逐项在两次回答中挑较好的判断。随后仍用相同 A/B 代码，B 为主、A 为次；Phase 维持 H0。这个辅助层的回退与严格 factored 的整帧回 H0 不同，必须单列，主要因果对照是 repeat 与 memory 两臂。

## 工程与预算边界

最多 **18 次新 POST（9×2）**，不重新生成 H0/候选，不使用 Batch，无自动重试。仍为 Qwen `qwen/qwen3.8-max-0902`、严格 Alibaba、temperature=0、reasoning=low、max_tokens=4096；说明上限仍是严格 1000，本试验不混入新的长度归一化规则。

旧冻结派发器限制最多 6 张图；部分补图请求会有 7 或 8 张。新独立实验入口只将此图片数量上限明确扩到 8，其他文本、尺寸、总图片字节和上下文上界不变。保留同一个原生发送与费用入口、逐次 $2.60 预留、开发 $8／整个目标 $12 的追加账本，失败或未知费用不当免费。执行前重核公开价格和实际输入边界。扩图后供应商是否接受，以实际响应为准，失败不重试绕过。

当前已完成开发阶段累计 118 次、$1.716158，全部结算。新输入、额外图片、源码、旧请求及原生响应、协议在调用前绑定 SHA。repeat wire 必须与首次实际派发吻合；从 memory 删除额外图片及必要元数据后应能恢复原输入。首次付款前完成针对性测试与离线预检。

## 评价与决策

所有 16 个目标、两臂输出先保存，再关联 Training GT。报告首次 names、repeat、memory 的 A/B；保留 H0、H1 对照。统计五头 F1／集合 Accuracy、有效 GT、改对／部分改善／改坏／mixed／等损失替换／保持、候选有益／有害修改实际应用、额外调用失败与回退、实际费用。额外请求失败后回首次结果并不是审核质量改善。

首先比较 memory B 与 repeat B，判断新增画面是否带来增量；再分别与 H0 比较实际修复价值。候选仍冻结，H0/H1 共同漏检的 12 个真实 IVT 出现项仍不可能由这次审核补出。多轮使用这 16 个 Training 目标属于方法开发，不是独立泛化验证。

进入确认的开发筛选沿用明确的实用条件：IVT F1 高于 H0、IVT 集合 Accuracy 不低于 H0、有益 IVT 修改应用数多于有害修改、I/V/T 各头 F1 均不低于 H0。若 memory 通过，还需 IVT F1 高于 repeat、集合 Accuracy 不低于 repeat，且组件 F1 不低于 repeat，才将新增图像视为有价值的待确认机制；若只有 repeat 通过，只能说明条件追加审核值得确认，不能记为 memory 成功。两者均通过但 memory 无明确增量时优先较简单的 repeat。

该筛选不代表统计显著性或默认部署标准。只有在完成 Training 审计后才冻结单一方案进入少量 Validation 确认；不根据 Validation 成绩再改方案。若均无实际净收益，保留 H0、报告局限，不继续增加模块。Testing 始终不用于调参或选择。
