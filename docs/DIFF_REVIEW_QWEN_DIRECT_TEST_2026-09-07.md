## 查到的机制问题

**一、删除操作与“标签存在性”混在同一个审核对象里，出现含义反转。**

现有契约规定 `CONTRADICTED` 是“图像反对该标签存在”。然而，对 `target:REMOVE:2` 和 `ivt:REMOVE:58`，Qwen 的文字明确描述原标签可见、删除不成立，同时枚举却填 `CONTRADICTED`。这与契约自相矛盾，说明该回答把枚举理解成“反对这次删除操作”。Python 按既定枚举解释为“原标签不存在”，于是 B 真正删掉了两个正确标签。

这不是 JSON 缺字段，也不能解释成单纯“模型没有看见正确标签”：文字恰恰支持保留。Schema、真实图片引用和全帧声明都通过检查，也不能保证枚举与文字表达一致。A 在这个目标保留 H0，是因为另一项新增被拒绝，不是程序识别出了该矛盾。

**二、通过逐项审核仍可能接纳错误的 null 候选。**

另一个目标中，Qwen 将第二把器械“没有清楚的已定义接触”解释为支持 null Verb/Target/IVT，三项一起接纳，但与 GT 不符。这提示还需区分动作证据不足、视觉误判及 null 类别定义理解；本次结果不能单独确定哪一个是根因。`full_frame_reviewed=true` 是模型声明，不能当作独立正确性证据。

建议下一项最小修正是让模型只回答中性标签命题的 `PRESENT / ABSENT / UNCLEAR`，由 Python 单独映射到增删操作，避免用 `SUPPORTED / CONTRADICTED` 同时承载标签和修改两种含义。需要用新的预先固定样本验证，不能根据这里的两个 GT 写特判。即使解决含义反转，也不能保证 null 判断或候选漏检得到改善。

本轮没有实施这项新语义修正，也没有继续付费调 prompt。保留冻结 H0，A/B 都不提升为默认方案。
