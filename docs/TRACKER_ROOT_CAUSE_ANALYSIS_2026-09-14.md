# Tracker 到最终标签的收益传递诊断

结论：现有 Tracker 有可利用的器械识别与定位信息。当前主要问题是这些信息进入系统太晚、被压缩为粗粒度统计，且候选池和接纳规则限制了它改变最终答案的范围。本次不能证明某个新接法已经提高最终 IVT；但数据足以否定“Tracker 没有额外信息，所以应该放弃”的判断。

本次仅检查代码并统计已有 6,059 条 Training 观测。没有新增 API、训练、Testing 访问或修改默认、权重、冻结实验。路由统计来自最终拟合 Qwen 模型的历史训练缓存回放，不是外层留出成绩。新增诊断保存在 `artifacts/preflight/tracker_root_cause_20260914_r1/`。

## 1. Tracker 确实有额外信息，但检测质量不等于关系识别或跟踪质量

已核验的九视频 OOF 器械检测结果为 Precision 85.86%、Recall 84.61%、F1 85.23%、macro AP50 62.65%。这些指标匹配器械框，不衡量动作、目标组织、IVT 或跨帧身份准确率；VID31 无有效框 GT，不在这些检测指标里。

本次在与 Gate 完全相同的 6,059 帧上，把当前帧预测框的器械类别去重，与已有五头 GT 的器械类别集合比较：

| 类别存在性口径 | TP | FP | FN | F1 |
|---|---:|---:|---:|---:|
| H0 | 8,458 | 977 | 1,605 | 86.7576% |
| Tracker 当前帧类别集合 | 9,444 | 591 | 619 | 93.9795% |

这个 93.98% 不做框匹配，也包括 VID31，不能与九视频的 85.23% 框检测 F1 当作同口径提升。它说明在当前开发数据上，Tracker 的器械存在性信息优于 H0。

Tracker 找到 H0 漏掉的 1,204 个正确器械标签，其中 1,091 个没有进入现有候选池。即约 90.61% 的这部分补漏线索没有获得审核机会。同时，Tracker 相对 H0 新增的类别中也有 377 个错误标签，不能直接当作真值接纳。

`tracking/associator.py` 实现同类别 IoU 匹配和 Hungarian 关联。本次未获得 HOTA/IDF1 等身份指标；良好的检测 F1 不能证明所有 T1/T2 身份都稳定正确。

## 2. 两种接入方式都有明确的信息限制

### Gate 特征分支

`research/gate/final_only_training.py:34` 定义 11 项 Tracker 特征：可用性、器械数、类别数、置信度均值/最小值、与 H0 的类别差异数、新增/消失/保留轨迹等。

`extract_features` 不向 Gate 提供框坐标、具体缺失类别、每个实例的运动或器械与组织的关系；历史变化只比较最后两帧的 ID 集合。位置和身份的丰富结构被压成计数。

`scripts/train_pgp_gemini38.py` 的监督为“歧义保护后的全审核输出是否不同于 cheap”，不是“Tracker 能把哪个实例的哪项关系修正”。该分支只决定是否继续调用原审核，Tracker 不改变 H0、候选或审核答案。它主要能改路由，不能直接创造新的识别能力。

### 后续审核证据分支

`scripts/run_pgp_tracker_evidence.py:8` 只给非 Qwen 的后续交互审核员附加 Tracker。H0、proposal、Qwen 初审、Gate 和 Phase 分支都不消费这些证据。

最终拟合 Qwen 模型在这批缓存中放行 3,380 帧，其中 3,378 帧仍需要后续交互审核；仅约 55.75% 的帧具备该接口的使用机会。该统计是接口覆盖，不是 Gate 泛化表现。

`tracker_evidence.py` 保留原图，仅附加框坐标、类别、置信度与局部 ID；没有生成实例关系。其指令明确要求只判断已有候选、不能新增候选。正确关系不在池里时，后续审核无权补入。

## 3. 候选池和后处理显著限制 IVT 补漏

相对 cheap，6,059 帧共有 7,687 个缺失的正确 IVT 标签。按现有候选池及冻结规则做互斥分解：

| 首个结构性障碍 | 缺失标签数 | 比例 |
|---|---:|---:|
| 不在候选池 | 6,278 | 81.67% |
| 在池中，但被 grasp/retract 歧义保护锁定 | 1,079 | 14.04% |
| 在池中且非上述歧义类，但低于 H0 Phase 先验 veto 阈值 | 164 | 2.13% |
| 剩余，尚未考虑 Gate、无效证据和分量评分限制 | 166 | 2.16% |

这张表只诊断“补回 cheap 漏掉的正确 IVT”，不包括删除错误 IVT、其他四头的修复，也不是预期效果或新方法成绩。最后 166 个仍不保证可修复。

关键实现：

- `candidate_coordinator.make_pool` 从 H0、proposal 和已有池建立候选，并补 IVT 的分量；没有 Tracker 补候选入口。
- `recent_mean_panel.select` 只在池内接纳。新增 IVT 除自身均分达标外，三个分量均需达标。
- `prior_gated_repair.select_prior_gated` 在评分选择之后按 H0 Phase 做先验 veto/add；低频正确候选也可能被否决。
- `pgp_ambiguity.repair` 将 grasp/retract 以及所有对应 IVT 的成员关系恢复为 cheap，既防止伤害，也阻止这些类别的正确修复。

因此，调整 Gate 阈值或给剩余审核员更好的器械框，无法越过这些固定的输出限制。

## 4. 两个配对案例的具体原因

### VID103_5626

H0 与 Tracker 的器械类别均为 grasper、hook，器械头已完全正确。GT target 为 peritoneum/null_target，池中只有 gallbladder/cystic_plate；GT IVT 11、96 均不在池里。

全五席已采集回答的离线汇总中，两组都能在歧义保护前加入 grasp；之后该标签被恢复为 cheap 的状态。这个汇总不是实际早停路径，不能冒充实际已调用全部五席。实际回放输出两组一致，仅停止深度不同。

另外 H0 Phase 为 3、GT 为 1；先验按 H0 Phase 处理，Tracker 证据分支不影响 Phase。该例的错误不能通过再次确认器械种类解决。

### VID23_501

Tracker 当前帧有两个不同 ID 的 grasper，以及一把 hook。去重的器械类别集合仍只有 grasper、hook，所以器械头的 100% F1 隐藏了两个同类器械分别执行不同关系的问题。

GT IVT 为 17、20、61，cheap 为 17、96：61 不在候选池；20 在池中但属于锁定的 retract 类。Tracker 组 target_10 达到均分 4.2，最终补入 omentum，故 target 改善；IVT 没有改善。IVT 20 的均分本身仅 3.4，说明即使单独取消保护也不能声称这次就会补回它。

对照组 Gemini 回答无效，导致所有候选缺少有效五席均分；Tracker 组未发生同样的整条无效情况。这一格式/证据有效性差异仍阻止把单帧结果归因于稳定的 Tracker 语义收益。

## 5. 无效证据与早停是另一个障碍，但不是简单的循环 bug

`recent_mean_panel.aggregate` 对任一审核席无效的候选返回 `None`；`pgp_runtime.settled` 将已观察到 `None` 的候选判为已确定。这与“该候选无法形成有效五席均分，保留原结果”的规则一致。

精确早停的目的，是保留现有完整审核规则的最终结果；关掉早停并不会自动修好这套接纳规则。3,066 帧的 Qwen 初审至少有一个非歧义候选无效；这包括逐候选证据契约无效，不等于 3,066 次整条 JSON 解析失败。

也不能直接删除全部保护：VID23 的 Tracker 五席汇总中错误的 grasp 可达到 4.8，当前保护恰好阻止了这一错误新增。新接纳机制需同时测修正和伤害。

## 6. 最值得验证的 Tracker 使用方向

优先改接入位置与实例输出契约，保持 Tracker 权重冻结：

1. 在候选生成之前使用当前帧 Tracker 的类别与实例，先验证把 H0 漏掉的器械作为候选带入系统。补候选与直接改最终标签应分别测量；不能把新增候选自动视为正确。
2. 让现有提案请求按具体 `track_id` 观察“这一个器械实例正在对什么组织执行什么动作”，生成可新增的、有图像证据的关系候选。保持全图上下文；框不被当作末端、接触或动作真值。身份不可靠时保留当前帧独立实例，不强行跨帧合并。
3. 同类不同实例允许分别产生关系。仓库的 `instrument_extraction.py` 按 `instrument_id` 每类一行并拒绝重复类别，无法直接表示两把 grasper；不能只把该旧模块接上就当成实例方案完成。
4. 先单独检查器械补漏、关系候选覆盖与错误候选数量，再检查新证据在接纳前后被保留还是丢失。在识别增益得到验证之后，才重新校准适用于新候选/审核分布的 Gate。旧 Gate 与旧缓存不能自动代表修改请求后的效果。

这不是“再多加几张裁剪图”：9 月 9 日已做过 proposal 当前 ROI、同坐标时序 ROI、审核 ROI；当前 ROI 的 24 目标确认修正 4 项、引入 7 项错误，未通过。新的可检验假设应是按实例组织关系和打开候选生成通路，单纯加框或放大不能预承诺有效。

本次仅提出研究优先级，未实现或付费验证上述新方案。旧模型和规则继续作为对照保存。
