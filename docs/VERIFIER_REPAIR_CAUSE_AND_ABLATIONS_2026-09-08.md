# 为什么保留 H0，以及这次具体修了什么（2026-09-08）

> 2026-09-08 文档发布说明：本页保留实验结束时的结果及 Git 状态；“未提交”等表述不是本次发布状态。完整机制索引与当前发布范围见 [汇总](VERIFIER_REPAIR_EXPERIMENT_SUMMARY_2026-09-08.md)。近期本地脚本、冻结源码与原始实验目录未随这次文档提交发布，文中相关复现命令需要本地产物。

结论：H0 保留为冻结初始预测和对照，不代表答案正确。此前修复仅在四个完整标注 Training 目标上改善 Verb，
没有改善 Target/IVT。本轮又完成候选补充、有效票处理、联合反思和跨视频标注参考的对照，
**仍未取得 IVT 净收益，不能宣称 Verifier/Repair 已成功修复语义准确性**。这些研究分支均未替换默认纯 API 入口。

## 第一问：最新链路和保留 H0 的原因

此前可运行研究链路为：冻结 Qwen H0 → Gemini 3.8 Flash 补候选 → Python 合并并绑定候选 ID →
五个视觉审核者逐项给评分和证据 → Python 检查修改、分歧和组件依赖 → 接纳局部修改或保留 H0。
审核五席为 Grok、Qwen、GPT、Gemini、DeepSeek；候选模型与 Gemini 轻量审核席是不同模型。

“保留 H0”有两层：所有对照固定同一份初始答案；研究方案未证明可靠净收益前，默认入口继续只输出 H0。
研究入口确实能修改最终答案，没有把所有修改硬编码成 KEEP。
上次 H0 / 新审核的 Verb F1 为 76.92 / 85.71，Target 均 16.67，IVT 均 14.29。
新审核减少误改，但挡住了旧审核能完成的一次有益 Target 修改，因此尚不足以默认启用。
这些分数只描述四个困难小样本，不是整个 Training/Testing split 的分数。

## 已核实的原因

### 1. 分数为什么这么低

四个目标为 VID103/14576、37226，VID23/9801、31001，五头 mask 均有效。
初始 Target 为 TP=1、FP=5、FN=5，micro-F1=2/(2+5+5)=16.67%。
初始 IVT 为 TP=1、FP=5、FN=7，micro-F1=2/(2+5+7)=14.29%。两者集合 Accuracy 都为 0。
这不是“模型信心只有 16%”，而是标签集合与 GT 比较后的指标。

独立审计直接读取原始 `vid103.json` / `vid23.json`，与评分器输出逐项比较，未发现这四个目标的 GT ID/任务映射错位。
例如 VID103/14576 的原始 GT 为 `hook/dissect/gallbladder` 和 `grasper/retract/gallbladder`；
H0 仅输出 `hook/dissect/cystic_plate`。同时存在边缘器械漏检和操作对象错配。
VID103/37226 的 GT 则为 `hook/dissect/gallbladder` 与 `grasper/retract/liver`。
不能把此前出现 grasp 的个例推广为“牵拉都应该改成抓持”。

检查的两个 VID103 目标里，原始 GT 的器械 `visible=1`、`visibility=1`，并有正尺寸框；
一些 grasper 位于图像上边缘，`area=0` 也没有被用来删除它们。
因此本轮没有证据支持用“完全不可见 GT 被错误评分”解释这些错误。
[官方 CholecTrack20 说明](https://github.com/CAMMA-public/cholectrack20)区分可见、体内和术中轨迹；
这些跟踪范围与语义标签评分不可混为一谈。可见性、遮挡与类别标注定义仍需逐项核对，不能凭模型多数意见改 GT。

### 2. 候选补充存在设计缺口

`candidate_coordinator.make_pool` 原先只把 IVT 拆成 I/V/T 组件，未自动枚举已有器械/动作对应的其他合法目标组合。
所以发现一个新的 Verb，不会自动使正确 IVT 进入审核列表。上轮候选只覆盖 8 个 GT IVT 中的 2 个。

新增 `repair_v2.complete_target_hypotheses`：对候选池里已有的 Instrument/Verb，枚举本体中全部合法 Target/IVT。
这只是扩展待审核假设，不是自动赋标签；超过 64 项则保留原候选，不偷偷截断或按 GT 排序。
本轮候选覆盖提高到 **6/8**。仍遗漏的 2 个 IVT 涉及未进入候选的器械或动作，不能靠 Target 组合补齐。
这修补了候选生成的设计不足，但不代表新假设都符合图像。

### 3. 一项不合格意见会让整项候选无法改变

`semantic_coordinator.aggregate` 原规则：任一席该候选不合格，就把该候选有效分设为 3，保留 H0 状态。
上轮 38 个候选中，24 个因此阻止修改。删除的局部证据被拒绝本身有理由，但不能据此假定其余模型都没有有效证据。

新增 `aggregate_quorum` 把不合格意见记为弃权：至少 4 个有效席位、至少 3 个同方向意见，
有效均分达到新增 ≥4 / 删除 ≤2 才可能修改；明确支持和明确反驳并存仍阻止该项修改。
局部否定仍不能作为整帧删除的证据，缺失票不计成负分，所有弃权均记录。
这一放宽作为独立消融实现，但**实测增加了误改，没有采用为默认规则**。

### 4. 正确答案在候选中，模型仍会否认它

VID103/14576 上，原始审核记录的 `hook/dissect/gallbladder` 五席评分为 1、1、4、1、2（按 DeepSeek/Gemini/GPT/Grok/Qwen），
而错误的 `hook/dissect/cystic_plate` 为 4、5、3、5、4。错误候选的均分达到 4.2。
若模型把操作对象共同认错，均分和 JSON 完整性都不能变成正确性保证。
部分正向文字仍用“邻近解剖结构”支持 MATCH，程序只能验证结构，无法证明文字对应真实图像。

扩大候选后，遗漏的正确标签仍分别受候选缺失、低视觉支持、明确分歧或有效席位不足影响。
完整逐标签原因在 `repair_v2_diagnostic_20260908_v1/independent_audit.json`。
其中跨 I/V/T/IVT 四头的未恢复标签共 17 项：6 项不在候选、3 项视觉支持不足、7 项明确分歧、1 项有效席位不足。
这不是 17 个 IVT，也不是 17 个不同目标。

### 单次反思的实现

`reflective_repair.py` 验证 Gemini 3.8 Flash medium-reasoning 的联合修改：
输出四头最终集合及每项实际差异的证据；逐项核对 ADD/REMOVE、候选 ID、当前图引用、删除的全帧范围和组件依赖。
没有证据的实际修改、重复/未知候选、方向矛盾、删除仍被 IVT 使用的组件均拒绝。
该分支只有一次复核，没有循环自称“已正确”，也没有用 GT 选择模型答案。
四次调用均取得可解析回答，两个 KEEP、两个有效 PATCH。两项 PATCH 的语义仍有错误。

### 跨视频标注参考图对照

针对相同 H0 器械/动作组合的两个 VID103 目标，按本体找所有合法类别，从其他 Training 视频每类固定取中位时间样本。
没有查询当前目标 GT 来选择参考类别；VID103 整个视频被排除。
取得五张参考：VID23/12751（57）、VID96/18851（58）、VID23/10776（59）、VID23/23251（60）、VID23/2926（61）。
类别 56、62 无可用参考，不补造图片。参考提供其自身 GT 关系和器械框，不提供查询目标的 GT。

该实验是**监督参考辅助**，不属于纯 API 基线，也不是独立验证集：两个目标此前已被分析过。
参考图与查询三帧明确分开，参考图不冒充过去帧；任何修改仍必须引用当前查询图。
此外修正请求预算按实际图片数预留，避免加入参考图后仍只按三张图计算。

两次调用均返回 KEEP，Target/IVT F1 均保持该两目标 H0 的 0；Instrument/Verb 各 66.67，Phase 100，均未变。
两目标零改善、零改坏、零等损失替换。这个有限参考图试验无收益，不能推论所有 RAG 方法无效；
KEEP 本身也不足以判断模型是视觉上仍认错，还是遵循了保守修改要求。
