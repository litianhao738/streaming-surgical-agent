# Training 先验图谱辅助候选生成（2026-09-08）

状态：独立实现、8 目标真实 API 对照、离线评分和原始请求审计已完成。相对本批原修复对照，IVT micro-F1 从 34.48% 到 40.00%，Target 从 55.17% 到 57.14%，但 IVT 集合 Accuracy 仍为 0/8；四组独立配对审核耗时的中位增幅为 14.32%，未满足 ≤10% 的目标。保留为实验版本，没有替换默认入口。原纯 API H0、原修复入口、上一轮 Graph 检索实验和训练输出均保留。

## 改动位置和实际来源

```
共享 Gemini H0
  ├─ 原补候选模型调用 → 原五席并行审核 → 原规则修复
  └─ 留出统计图谱给最多两个完整IVT备选
       → 同一个补候选模型调用 → 原五席并行审核 → 原规则修复
```

本次先实现用户选中的第一项：让知识图帮助补候选。已接入 Training GT 统计，使用原有 `video_counts`／`fit_prior`：按任务 mask 排除无效 GT，统计完整 IVT 的帧级出现频率及其与 Phase 的关系，按视频平衡频率。完整 IVT 的组件关系来自项目现有 `ivt_components_v1.csv`。这属于 Training 先验与本体关系辅助候选生成，没有新增医学外观知识、参考图片、模型训练、Tracker 推理或记忆模块。

每个查询视频使用**排除该整个视频后重新拟合的表**；其余 Training 视频允许参与离线拟合。当前实际上只有另外三个视频提供有效 IVT 监督；仅有 I／Phase 监督的视频不会贡献 IVT 负例。Validation、Testing 不参与拟合、选择或调参。本次是开发阶段的按视频留出检索，不是完整系统或 Gate 的 OOF 泛化实验。

仅从有统计支持的同器械关系中检索：第一槽优先用 H0 预测阶段的先验，不足时退回全局；第二槽用全局先验。优先查看已有 IVT 只改变一个动作或目标的关系；H0 只有 null 时允许同器械的非 null 备选。统计资格沿用既有规则：至少 100 个有效帧、3 个有效视频、5 个正例帧和 2 个出现该标签的视频。排序规则在调用前冻结，没有按本批 GT 选备选。

最多两个备选加入补候选请求的 `candidate_relation_hints` 字段。提示明确：来源为其他 Training 视频，H0 阶段可能错误，统计不是当前画面的视觉证据，稀有／未列出的关系仍可提出，不能机械复制。模型仍可返回空；新增 IVT 总上限保持 4，不改变输出 schema、图片、模型或阈值。五席不接收先验文本、频率或候选来源，只审核模型最后提出的候选。

本实验把 Training 统计和本体候选提示作为一个组合改动，不能仅凭结果归因于“图结构优于普通统计”或某一个排名规则。

## 固定样本和运行约束

按时间分位和五头 GT 可用性选八个新目标，距离历史实验与已规划目标至少 75 个原视频帧；未按 GT 内容或分数选择。四个视频各两帧，对照顺序交替。

| 视频 | 帧号 |
|---|---|
| VID103 | 18326、33576 |
| VID23 | 13176、28876 |
| VID31 | 40701、73701 |
| VID96 | 15051、26051 |

三帧仍是 `[t-50,t-25,t]`。H0／补候选使用 OpenRouter `google/gemini-3.8-flash`；五席沿用上次的 Grok、Qwen、GPT、Gemini、DeepSeek 模型、路由及推理设置。默认纯 API 入口的 Qwen H0 配置不变。

| 角色 | 本次实际请求模型 | 通道／路由 |
|---|---|---|
| H0、补候选 | `google/gemini-3.8-flash` | OpenRouter，Google AI Studio |
| Grok 审核 | `grok-4.6` | xAI 直连 |
| Qwen 审核 | `qwen3.8-flash` | 阿里云工作空间 |
| GPT 审核 | `openai/gpt-5.6-luna` | OpenRouter，OpenAI |

| DeepSeek 审核 | `deepseek/deepseek-v4-flash-vision-exp` | OpenRouter，Fireworks |

两组共享 H0，各自生成候选池；每组一轮。每目标最多 1 次 H0 + 2 次补候选 + 2×5 次审核，即全实验最多 **104 次 POST**。OpenRouter 上限 $2、xAI 上限 $2、阿里云上限 ¥2，无自动重试。若完整请求相同，原始回答连同失败共享，避免重复花费和伪造差异。单个部署分支的调用次数保持 1+1+5，实际五席耗时仍可能受候选数影响。

成功标准不只看候选覆盖：需要最终 IVT F1 或集合 Accuracy 提升，同时 Target 指标不降、总标签错误不增加，并报告其他头的损伤。五席配对耗时中位增幅目标 ≤10%；小样本供应商波动另列。缺失 GT 按任务 mask 排除；全部付费输出关闭、快照哈希核验后再独立评分。

## 实验结果

两组始终共享同一份新 H0，补候选各调用一次；新增 IVT 上限仍为 4，总候选池上限仍为 64。审核使用五个有效评分的算术平均，固定阈值 4：新增 IVT 除自身通过外，三个组件也要各自通过；无效／模糊证据保留当前标签。删除需满足原有反证规则，独立头不由 IVT 全量重建，Phase 保持 H0。每组只跑一轮，未用本批 GT 改阈值或再调规则。

### 改对、改坏和无收益替换

“部分改善／改坏”按五头有效标签的 FP+FN 总数减少／增加计；“全部改对”要求目标的所有有效头都完全正确。每个头的每个错误分别计数，IVT 与其组件错误不会合并成一个事件。

| 比较方向 | 全部改对 | 部分改善 | 改坏 | 无收益替换 | 未变化 | 修正标签错误 | 新增标签错误 | 总错误前→后 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| H0 → 原修复 | 0 | 4 | 3 | 0 | 1 | 5 | 4 | 57→56 |
| H0 → 先验图谱修复 | 0 | 4 | 2 | 0 | 2 | 6 | 3 | 57→54 |
| 原修复 → 先验图谱修复 | 0 | 2 | 0 | 0 | 6 | 2 | 0 | 56→54 |

相对 H0，新分支正确新增 5 个标签、正确删除 1 个器械标签、错误新增 3 个标签，没有错误删除。两处改坏为 VID31/40701 错增 `grasp` 与 `grasper/grasp/gallbladder`，以及 VID96/15051 错增 `coagulate`；这两处在原修复分支同样发生。不能把“相对原修复没有新增改坏”写成“修复不会改坏 H0”。

### 收益实际来自哪里

1. **VID103/18326：正确 IVT 7（grasper / grasp / gallbladder）从未接纳变成接纳。** 原候选已经包含 IVT 7；加入先验后，其他候选由 IVT 4 改成 IVT 60，五席对 IVT 7 的评分由 `[4,5,3,5,1]`、均值 3.6，变成 `[4,4,4,5,4]`、均值 4.2，组件也通过。它是这次实际的 IVT 得分收益，但不能描述成“图谱第一次找到了该正确答案”。审核未见先验文本，差异可能来自候选上下文变化或模型调用波动；每组仅一次请求，无法分离二者。
2. **VID23/13176：避免错误新增 Target 4（cystic_pedicle）。** 原补候选提出 IVT 84／Target 4，Target 的均分 4.0 导致错误新增；先验分支未提出它，因此保留 H0 的 Target 集合。评分器在两分支间记为一次正确删除，但运行机制是避免错误新增，并非从 H0 删除原标签，也不是 Verifier 成功反驳了该组织。
3. **VID103/33576：图谱确实补出原候选没有的正确 IVT 60，却没有形成最终收益。** 原池只有 IVT 59／64，先验池有 59／60；GT 为 60（hook / dissect / gallbladder）。五席对 60 的分数为 `[4,1,2,1,4]`，均值 2.4，达不到新增阈值；错误 IVT 59（hook / dissect / cystic_plate）反而均值 4.6。原始文字集中在“胆囊”与“胆囊床／cystic plate”的作用对象区分。即便移除组件否决，IVT 自身也未通过，因此这处失败不能主要归因于组件接纳限制。

相对 GT，上述第三处是审核语义判断错误。原始解释显示类别理解分歧，但仅凭回答文字不能进一步确定是像素看错、标注口径理解不一致，还是三帧证据不足；没有把 GT 反向写入 prompt。

### 候选瓶颈与先验限制

| IVT 计数（按目标累计） | 原修复 | 先验图谱 |
|---|---:|---:|
| GT 正例 | 15 | 15 |
| 池内正确 IVT | 6 | 7 |
| 池内错误 IVT | 15 | 15 |
| 池对 GT 的覆盖率 | 40.00% | 46.67% |
| 最终正确 IVT | 5 | 6 |
| 最终错误 IVT | 9 | 9 |

图谱共给出 15 条备选，其中只有 4 条属于该查询目标 GT；补候选模型采用其中 7 条。最终保留的 3 条先验备选中，2 条正确、1 条错误。先验是“其他手术中常见”，并不等于“这张图确实有”。

新分支仍有 **8 个正确 IVT 未进入候选池，1 个已进入但未被接纳**；H0 原有的 8 个错误 IVT 全部保留，另新增 1 个错误 IVT。这解释了 F1 虽上升，但没有一帧 IVT 集合完全正确。

已确认的机制边界：图谱只围绕 H0 已认出的器械检索，H0 漏器械时无法靠此检索直接补对应 IVT；阶段检索也受 H0 Phase 错误影响，虽保留全局槽但不能消除偏差。每个查询仅另有三个有效 IVT Training 视频支持先验，覆盖与类别频率不稳定。VID31/73701 已提示正确 IVT 17，模型仍返回空补候选，说明“提示备选”本身不能保证视觉模型提出它。

### 调用、费用与时间

实际 **84 次 POST**：8 次共享 H0、16 次补候选、60 次五席审核。四对完全相同的审核请求共享原回答，少发 20 次 POST；其余四对分别实际调用。单分支仍是每目标最多 7 次，不额外调用图谱模型。

84 次均完成 JSON 解析，没有传输失败导致的整组回退。证据规范化仍拒绝部分单项判断：原对照有 17 项局部观察不能否定整帧、1 项分数与结论矛盾、1 项单项 schema 不合格；先验分支分别为 14、1、0。这些被拒项不会伪造平均分。每组均 7 个 `UNRESOLVED`、1 个 `MODEL_PASS`；唯一 `MODEL_PASS` 的 IVT 仍未集合全对，审核通过不代表 GT 正确。

#### 补充：候选与审核合起来的总时间

为回答“相对上一版总共增加多久”，从封账的原始计时重新计算。这里的“上一版”指本次同批 `control` 的一轮无图谱修复，不是不同目标上的历史多轮实验。

| 同一批四个独立配对目标 | 原修复合计 | 新分支合计 | 总增量 | 总增幅 |
|---|---:|---:|---:|---:|
| 已有 H0：补候选请求＋五席并行阶段＋新分支检索 | 93.76 秒 | 103.41 秒 | +9.65 秒 | **+10.29%** |
| 再计入各自相同的 H0 调用耗时 | 119.46 秒 | 129.11 秒 | +9.65 秒 | **+8.08%** |

已有 H0 时，以上相当于每目标从平均 23.44 秒到 25.85 秒，增加 2.41 秒。新分支四目标检索本身合计约 0.037 秒；主要差异出现在模型请求。它是请求与已计时阶段的合计，未单独计入读图、局部修复／序列化，也未包括尚未集成的 Tracker／Gate，因此不能当作整个完整 Pipeline 已实测的总时间。

如果把四组相同审核的原始耗时分别回填到两个分支，可以重建八目标等效总量：H0 后 182.78→192.35 秒（+9.57 秒、+5.24%）；含 H0 为 232.73→242.30 秒（+4.11%）。这不是八组独立计时，不能用这个重建数字替换四组实际配对结果。前述 14.32% 是“审核阶段的逐目标百分比增幅中位数”，与这里“整个已计时修复链的总时间比值”口径不同。

机器计算与逐目标明细：`artifacts/preflight/prior_candidate_eight_20260908_v1/timing_total_comparison.json`。本次补算核对原 `completion.json` 中计划、预测和账本的哈希，未改动推理或产生 API 调用。全 Testing 的总时差仍需按实际 Gate 触发、任务调度和提供商吞吐重新测量。

### 验证、留档与结论

- 相关 18 项测试通过（9 项新增先验／评分测试、9 项原先验测试），新增 Python 文件 Ruff 通过。
- 付费前冻结推理源码、统计源、先验表、图片和模型配置；付费完成后再算 GT。评分器重建 16 个候选池、重放 16 组审核／修复，结果一致。
- 独立审计重新拟合 4 个排除查询视频的先验表、重建 8 份提示，完成 96 项精确审核／候选请求比较、104 项原始输出核对（含共享项）和 15 份评分表独立算术核对；H0 请求另外逐目标核对。
- 审计脚本曾因落盘 JSON 排序改变嵌套 JSON 字符串的键顺序而比较失败；已改成从原 H0 回答和候选生成函数重建原顺序，精确比对通过。仅修正审计重建方式，没有修改付费推理代码、预测或原始请求。
- 完整本地证据：`plan.json`、`completion.json`、`predictions.json`、`calls/`、`priors/`、`metrics.json`、`frame_deltas.json`、`scored_truth.json`、`audit.json`、`independent_audit.json`、`hint_attribution.json`。
- 可读机器摘要：[prior_candidate_summary_20260908.json](experiments/prior_candidate_summary_20260908.json)。本报告和摘要不含密钥或图像。

本轮结论是**出现有限的语义净收益，但未满足耗时目标，也未解决候选遗漏和错误审核**。收益只有两个目标，且关键 IVT 改善存在评分波动解释；不能宣布已经修好 Verifier／Repair，也不能宣布图结构优于简单先验。保留独立实验，不替换现有版本。下一步如继续验证，应冻结本规则，在新 Training 目标上做相同对照并核验重复评分稳定性；不按这八帧 GT 写特判或放宽阈值来追分。
