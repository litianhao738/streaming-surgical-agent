# Verifier / Repair：机制核实、论文依据与最小对照方案

日期：2026-09-06。状态：完成代码复核、原始论文检索和方案设计；以下新方案均未实施、未发起付费模型调用。本轮不改冻结 H0、历史预测、Tracker 训练或已有工作区修改。

## 当前靠什么运行

本文只讨论 `scripts/run_grounded_api_pipeline.py` 的 Gemini 实验链路。已核对当前实现与补充实验 plan 的源码哈希一致。

| 环节 | 运行依据 | 本地代码职责 |
|---|---|---|
| H0 | OpenRouter 的同一 `google/gemini-3.8-flash`，严格 Google AI Studio 路由 | 使用冻结主 H0 构造器、prompt、完整本体和 final-only Schema |
| Locator | 同模型的另一次同步请求；不看 H0 答案 | 检查框坐标，按框从真实目标图裁剪 |
| 候选 H1 | 同模型看因果原图和裁剪；不看 H0 答案 | 汇总逐实例 IVT，再投影成 I/V/T；Phase复制H0 |
| Verifier | 同模型看原图、裁剪、匿名顺序的H0/H1集合 | 校验复核输出与请求/目标/假设绑定 |
| Repair接纳 | 固定Python条件 | 选择整个H1或保留整个H0 |

没有加载单独训练的 Verifier/Repair 权重，没有正确性判别网络，没有本地推理大模型，也未使用 Tracker、Gate 或跨窗口记忆。`SUPPORTED`、四个证据布尔字段和 `preferred` 是 Gemini 的输出，不是经过训练或校准的置信度。Schema、ID范围和哈希检查属于确定性工程校验，不能判定视觉事实真假。

每目标最多四次模型调用、无自动重试和修复循环。发生可选阶段失败时保留合法H0。原始Qwen纯H0默认入口仍保留。

## 机制与代码的问题

| 定位 | 确定的代码行为 | 性质及影响 |
|---|---|---|
| `grounded_repair.py:148`；`grounded_pipeline.py:202` | 将实例IVT汇总为集合；Review没有收到Proposal的实例→IVT对应 | 契约信息损失。同类器械合并后，复核需要自行重建标签归属 |
| `grounded_repair.py:49` | Review只返回整体preferred和每实例支持字段 | 没有逐项的标签ID、增删动作、假设归属和证据引用，无法检查每个实际改动是否被审核 |
| `grounded_repair.py:169` | 支持布尔项、整体偏好、覆盖声明、观察文本长度通过即可接纳 | 执行符合现有规则，但规则主要信任模型自述；填写完整不等于视觉结论正确 |
| `grounded_pipeline.py:176`；`grounded_repair.py:95` | 覆盖靠模型声明，框只检查合法性与最小边长 | 没有可测的工具覆盖、关联或接触定位校验。最多3个实例是明确能力上限 |
| `grounded_repair.py:149`；`final_only_grounded.py:114` | 从IVT重建I/V/T并整份替换 | 修复隐含改变了H0独立头的组合策略，一个IVT错误可连带改坏多个头 |
| `grounded_repair.py:145` | 任一实例不确定或无IVT，整帧候选失效 | 有理由的保守取舍，但明确的器械证据也不能单独修复器械头 |
| `grounded_repair.py:149` | Phase总是复制H0 | 当前修复不覆盖Phase，不应宣传为五头完整纠错 |
| 同一个base request派生各阶段 | 同模型、同因果图片，裁剪也来自原图 | 新视图可能有帮助，但未引入新的时刻或可靠外部反馈，不能当成统计独立证据 |

另外有两个可明确定位的工程/表达问题：

1. **第7类器械的候选表达缺口。** H0器械ID为0..6，6是specimen_bag；实际100个IVT仅覆盖器械0..5。Proposal虽然允许instrument6，后续却要求非空且器械匹配的IVT，因此含此类工具的正确Proposal无法形成有效H1，任何有效H1的Instrument集合也不可能包含6。这不是本次四目标低分的已证原因，却说明当前Repair没有完整覆盖H0契约。
2. **循环导入。** 冷进程直接导入grounded_repair会在 `grounded_repair → api.__init__ → client → schema → grounded_repair` 处失败；实际runner的先后导入顺序避开了问题。应独立修复依赖关系并做冷启动导入检查，不能将其当成语义提升。

已经修复的集合排列、候选数量越界、坏响应回退和请求绑定问题不应再次列成当前未修复问题。

## 论文能提供什么依据

只采用原始论文、会议页面或作者项目；以下是机制参考，不是这些方法已在本项目有效的证据。

| 论文 | 原文发现/设计 | 对本项目的借鉴与边界 |
|---|---|---|
| [Huang et al., Large Language Models Cannot Self-Correct Reasoning Yet，ICLR 2024](https://proceedings.iclr.cc/paper_files/paper/2024/file/8b4add8b0aa8749d80a34ca5d941c355-Paper-Conference.pdf) | 在所测文本推理任务中，无外部反馈的自纠错会失败或降分；强调区分GT oracle反馈与真实自纠错 | 必须计算改好/改坏和成本，不能把GT辅助选择当线上收益。这不是所有VLM都无法纠错的定理 |
| [Madaan et al., Self-Refine，NeurIPS 2023](https://arxiv.org/html/2303.17651v2) | 同模型生成、反馈、修改，在若干文本/代码任务中有效；具体可执行反馈有价值，错误检测仍是限制 | 可借鉴反馈粒度，不能照搬多轮或总体平均提升；论文没有验证本项目手术IVT |
| [Dhuliawala et al., Chain-of-Verification，Findings ACL 2024](https://aclanthology.org/2024.findings-acl.212.pdf) | 将事实核查拆成问题并隔离回答上下文；其消融中开放式事实问题优于部分yes/no变体 | 把泛泛支持项变成具体事实核查值得测试。当前Proposal已经盲于H0，不能把另一次盲生成改名当成新方法；上下文隔离不代表错误统计独立 |
| [Gao et al., RARR，ACL 2023](https://aclanthology.org/2023.acl-long.910/) | 寻找外部支持，再尽量保留原文地修订不受支持内容 | 可借鉴只修改有证据的部分；论文是文本归因修订，不能直接照搬为IVT增删规则 |
| [Gou et al., CRITIC，ICLR 2024](https://arxiv.org/html/2305.11738v3) | 借助搜索、执行等工具反馈批评和修订输出，包含无工具对照 | 指向可检查的外部反馈。Tracker可提供器械位置/身份线索，但不是动作和组织真值；裁剪工具执行成功也不等于框正确 |
| [Surís et al., ViperGPT，ICCV 2023](https://arxiv.org/abs/2303.08128) | 将视觉任务组织成可执行的视觉/语言工具调用 | 可借鉴把定位操作落实为具体工具。本项目已有真实裁剪，单纯再加crop步骤没有新意；无需复制其代码生成架构或新增多模型系统 |
| [Nwoye et al., Rendezvous，Medical Image Analysis 2022](https://arxiv.org/abs/2109.03223) | 围绕器械进行空间注意，并建模器械、动作、目标之间的关联 | 说明IVT任务需要正确关系对应，不能只得到三个类别集合。它是训练过的识别网络，不是现成的API Verifier |

这里没有将“同模型偏袒自己”作为已证原因：H0/H1本就同源，偏好也可能来自视觉误判、问法或顺序。现有A/B位置已轮换；额外双顺序调用只能作为另行预注册诊断，不能未经验证就把线上调用翻倍。

## 方案A：逐项核验差异，第一版仍整份接纳（优先，1–2天）

**只改变复核和复核结果校验，冻结H0、定位、候选、模型和图像。**

Python先计算H0→H1每头的实际增删，并给每项唯一change_id。Review在原有一次调用内返回：该change_id的可观察事实、反证、图片/裁剪引用，以及 `SUPPORTED / CONTRADICTED / INSUFFICIENT`。先要求回答“哪个区域呈现什么接触/运动”，再说明这支持哪项修改，避免只返回笼统的yes/no支持。

候选新增IVT可附带真实的候选实例归属，但不给H0虚构实例身份；无法对应时必须声明未知。保留原始全图，以免只核对裁剪范围内的实例。新增要求正面视觉支持；删除要求明确反证，不能将未看清当作不存在。

本地校验：change_id必须精确覆盖全部修改、无多余项；引用必须存在且属于本请求；所有实际变化得到支持才接纳整个H1，否则KEEP。字符串长度不作为语义证据。保持一轮Review，不增加模型调用，不使用模型自报置信度作阈值。

**能解决：**复核没有明确覆盖实际修改的问题，可能减少误接纳。

**不能保证：**模型的观察是真的，也不能补回H0/H1共同漏掉的正确标签。可能过度拒绝；全部KEEP不算成功。这个方案不是完整复刻CoVe，其借鉴点是具体事实核验。

主要改动位置：新的review schema、`grounded_pipeline.py`复核输入、`final_only_grounded.py`/接纳器差异覆盖检查；历史版本保持不动。

## 方案B：允许经过核验的最小修改，保留独立器械头（后续，1–2天）

**依赖方案A提供逐项证据；不能拿现有整体preferred直接做局部拼接。**

将Repair输出改成有范围的修改记录：独立器械证据、增删IVT及其必要组件变化。Python从原始H0复制，应用通过验证的修改组；未被修改的头/标签保持原样。

必须处理以下边界：

- 同类不同器械可能贡献同一帧级标签。不能因一个实例无此动作就删除全帧标签；删除需要全图覆盖与明确反证。
- 新增/修改的IVT及必要组件作为一个修改组验证；存在依赖冲突或越界时拒绝该组，不任意拼接各头。
- 不强迫原H0所有独立头等于IVT严格投影，不重写无关H0标签。
- 器械6允许作为独立器械事实被保留或核验；不能为其捏造不存在的IVT/null类。
- Phase继续固定。若做Phase修复，应是另外的实验。

**能解决：**整帧替换的连带影响与器械表达缺口，给“器械明确、交互不明确”留下可审查的修复路径。

**风险：**实例归属不清、共享标签依赖和拼接一致性使实现复杂度高于A。它不会自动使动作或组织识别更准。时间紧时先完成确定的表达/导入修复，不急于上线局部接纳。

主要改动位置：版本化Proposal契约、`proposed_labels`的替代实现和确定性补丁合并器；H0契约保持不变。

## 方案C：用现有Tracker提供定位证据（条件成立后1–2天）

将当前Gemini Locator替换为已经过核实的 corrected Tracker检测/轨迹输出；H0保持不变，Gemini仍负责候选与一次复核。这是更换定位信息来源的对照，不增加新的基础模型或多轮Agent。

Training必须使用与视频对应的真实held-out OOF结果，先核实训练日志、折分、权重哈希、帧覆盖和clip_to_frame_v2。当前没有据此宣称训练已经完成。

Tracker框是工具框，不能冒充尖端/接触点GT；在输入里标明box类型，保留上下文原图。Tracker只提供其能支持的器械位置、数量、身份与轨迹线索，不能把其分数当Verb/Target置信度，也不能把检测不到当成不存在。其错误需要独立统计。

**能解决：**尝试改善漏工具、实例对应和不可靠局部框，可能提高候选正确标签的覆盖。

**不能保证：**动作、组织或null判断正确。OOF尚未可用或框质量未验证时，不应为此占用本周关键路径。先不同时叠加新时序窗口、其他模型或新接纳器。

稳定运行时每目标最多三次模型调用（H0、候选、Review），另有本地Tracker耗时；这不代表必然降低总成本或提高精度。

## 两天内最值得做的对照

建议先选择A，不同时实现/测试三种机制。选择理由是改动最小、无需等待OOF，并可直接测出复核是否减少误改；候选上限低仍须如实保留。

拟定24个新Training目标：VID103、VID23、VID96各8个，按时间分布固定选择，避开已用于错误分析的目标；发起调用前冻结准确帧ID、因果图、样本来源、请求与源码哈希。只用GT可用性检查五头覆盖，不按标签值或预测误差选点。未通过mask预检则停止，不临时挑“容易修”的目标。

同一份H0、同一个Locator输出、同一个候选分别交给旧Review和A版Review。比较四臂：H0、未筛选候选策略、旧最终结果、新最终结果。候选不可用时各修复策略退回H0，不能移除失败样本。

最大模型调用数：24×(H0 1 + Locator 1 + Proposal 1 + 旧Review 1 + 新Review 1) = **120次**；没有变化/无候选时跳过相应Review。拟定本地消费停止预算 **$2**、不重试，发起前重新检查价格与请求大小；本地预留不等于供应商强制封顶。本轮未启动该实验，也未生成正式付费plan。

第一天完成版本化review契约、差异清单与离线检查。第二天在冻结规则后运行上述固定小样本并算分。已有四目标仅用于诊断/离线候选上限，不用其GT写规则或报告新泛化收益。

必须报告：

- 各头有效GT数量、micro-F1、集合Accuracy；缺失GT按任务mask排除。
- 改对/部分减错、改坏、等损失替换、保持、证据不足及候选不可用；单列完全改对和正确变错。
- 新增正确IVT数量与减少错误IVT数量分开统计，避免把删错标签当成识别出新正确动作。
- 候选自身的收益及旧/新Review的过滤行为分别报告。
- 每阶段调用、失败和新增费用，不把共享H0重复计费。

预先设定进入下一轮确认的条件：新策略相对H0及旧修复有IVT语义指标净改善，不能仅以拒绝更多、Schema合法率提高或全部KEEP作为成功；并检查其他头是否出现代价。24个目标仍只是筛查，不能证明总体优越。若没有清晰净收益，保留纯H0，完成实验报告与复现材料；Testing不用于本轮选择或调参。

上述论文提供设计线索和评估方法，不提供把某个新方案直接设为默认的依据。
