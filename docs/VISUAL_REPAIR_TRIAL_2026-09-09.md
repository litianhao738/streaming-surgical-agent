# 单视觉模型修订与反馈修复：同八目标实验

## 调用前固定方案

原图谱第一轮是对照；本实验不改变默认 H0 或原研究版入口。旧代码、模型输出和实验快照保留。

1. `repair_feedback_v2.py` 从同候选、同审核席的原始回答重新生成清洗诊断，核对 normalized reviews 一致，再传递具体拒绝原因。无效意见仍不计票、不作为已经核实的视觉证据。旧 v1 保留以重放历史实验。
2. `visual_repair.py` 接收 `changes`（ADD/REMOVE）和 `recheck`。替换用明确的 REMOVE+ADD 表达，完整本体内的池外标签也可提出。不要求提案模型自评分达到4分；提案不是接纳。每项修改仍有一句观察及当前图引用。
3. 新增 IVT 的必要组件仅作为派生假设，须独立审核。删除 IVT 不自动删组件；仍被保留关系需要的组件不能删除。Phase 不变。
4. 原未决候选和模型明确请求的 recheck 都能再次审核；不再以候选池未增长为停止依据。本实验固定检查全部八目标，包括原 MODEL_PASS，避免把模型通过误当真实正确。
5. 单个 `google/gemini-3.8-flash`（OpenRouter、Google AI Studio 严格路由，medium reasoning）读取原三帧、当前第一轮答案、完整本体、原图谱提示和修复后的观察反馈。删除反馈中的数值评分，保留可追溯审核席、判词、范围和观察。没有额外图像、Tracker 或 GT 输入。
6. 原 Grok/Qwen/GPT/Gemini/DeepSeek 五席只审核修订/复查项及必要组件。审核者看原图和命题，不看 Repair 自评、修改方向或其理由。五席均有效后取均分，新增≥4、删除≤2；组件约束沿用。部分席位无效不能冒充四票平均。

### 分阶段原因

- **候选覆盖没有提升。** 八个目标均未产生池外新ID；允许越池没有转化为模型实际补出新候选。IVT池仍覆盖7/15个GT出现项，8项仍在池外。该能力已由合成池外关系测试验证，但本次真实调用没有使用它，不能声称已经解决漏检。
- **单模型修改本身大多数错误。** 8项实际修改中，1项有益（删除一个错误Target），7项有害（5次错误新增、2次错误删除）。不是所有修改都先变好再被审核挡住。Repair仍混淆作用组织，以及grasp/retract类别关系。
- **审核有误放也有误拒。** 7项有害修改中6项未被接纳，1项被接纳；唯一有益修改未被接纳。最终相对R1多一个错误IVT，其他头不变。错误IVT得到完整有效五票 `[4,3,5,5,3]`，均分4.0；其组件也通过。因此这次最终损害不能解释成JSON失败或程序算错。
- **有益删除确实受到审核证据范围限制。** `VID31_73701 / target_2` 的删除与GT一致；五席有效评分为 `[None,3,3,1,None]`，Grok和DeepSeek因局部否定不足以删除整帧标签而无效。按固定规则保留了该错误Target。这暴露了审核限制，但本实验没有证明放宽它会产生净收益。
- **两份审核原回答存在格式冲突。** Gemini轻量审核席在 `VID23_13176`、`VID23_28876` 重复输出不同值的 `scope` 字段；兼容解析器以 `DUPLICATE_JSON_KEY / CONFLICTING_TYPE_OR_VALUE` 拒绝整份回答。不能选择其中一个值充当确定判断。43次HTTP均200；41份解析成功、2份安全拒绝。其对应候选有效均分缺失，相关回退保持在分母中。
- **不能把所有挡错都归功于视觉判断。** 比如错误grasp/IVT7，其余四席都是高分，因Gemini格式冲突而未通过。这里是流程回退挡住错误，不是五个模型已可靠识别错误。

本次反馈原始原因保留、显式修改、无新增候选仍可重审等工程行为已运行验证，但组合实验没有语义净收益。它不能单独估计反馈修复的F1贡献，也不能据此断言所有单模型Repair都无效。
