2026-09-09。用户授权测试后，使用原并行 Phase 实验的 8 个 Training 目标（VID103、VID23、VID31、VID96 各 2 个），复用 H0 和原四头候选池。两组均重新调用四头五席审核和独立 Phase 五席判断，每目标 20 次、计划 160 次请求。没有调用新 H0、补候选、Tracker 或 Gate。

## 固定协议

- 对照：原归档请求；候选：只替换 prompt 说明。原图、detail、帧顺序、候选 ID/名称/组件、标签边界、阶段定义、输出 Schema（文本内及 API 内）、模型、路由、思考强度与输出上限不变。图片重建后核对完整数据 URL 哈希。
- 五席仍为 Grok 4.6、Qwen 3.8 Flash、GPT 5.6 Luna、Gemini 3.5 Flash Lite 和 DeepSeek V4 Flash Vision Exp。
- 两组逐目标交替先后；每组四头和 Phase 共 10 次请求并行，目标之间顺序执行。原四头五份有效均分与组件依赖、Phase 五份有效响应下三票多数决均不变。
- 没有自动重试或按结果补抽。累计上限 OpenRouter $2、xAI $2、阿里云 ¥2，包含第一次兼容性失败批次的费用与未知预留。
- 首先冻结所有请求和源码，关闭调用并重放原始回答之后才读取 GT。Testing 不参与。8 个目标曾被观察过，属于开发对照，不是独立泛化验证。

预先成功标准：五头 F1 均不下降且至少一头严格提高；有效四头候选均分数量和有效 Phase 响应数不减少；80 对提供方实际输入 Token 全部可核实且新版本逐对不增加；计划 160 次全部派发。不因小样本通过就自动升级默认。

## 接口问题与修正

第一次 v1 批次运行了一个目标的两组、共 20 次请求。19 份 JSON 解析成功，精简 Phase 的 Qwen 返回 HTTP 400：JSON object 模式要求消息中出现单词 `json`。这暴露了先前离线结构检查未覆盖的接口要求。预算机制随后停止剩余目标，没有重试。

修正候选为 `verifier_compact_wording_v2_json_mode_candidate`：Phase 明确写 `Return only JSON matching response_schema`，不改变输出契约。新增 Qwen JSON 模式指令检查，33 项针对性测试和 Ruff 通过。重新进行完整两组对照，第一次未完成批次不混入质量比较。

修正后的历史 80 请求文本代理分词审计：四头减少 7.48%～7.62%，Phase 减少 3.39%。这些文本估算不包含图片及服务端封装；实际提供方 Token 和总体费用须以本次账本为准。

首次账本 `artifacts/preflight/compact_verifier_paired_20260909_v1/budget.json`；完整修正版目录 `artifacts/preflight/compact_verifier_paired_20260909_v2`。失败 Qwen 调用没有可核实 usage/cost，保留 ¥0.093794 未知预留，不声称它已实际扣费。第一次其余调用记录费用为 OpenRouter $0.01596551、xAI $0.052008、阿里云按 Token 估算 ¥0.026076。

入口：`scripts/run_compact_verifier_trial.py` 的 prepare/execute/score。执行目录单次使用，拒绝覆盖重跑；请求、原始回答、判断与计费均留档。

## 完整批次结果

完整 v2 在 60 次请求后遇到 Windows 账本文件原子替换的 PermissionError。60 份响应和对应 record 全部存在、完成时间齐全，原始调用已封存；问题发生在本地写入，不是未决 HTTP 请求。

续跑目录 `artifacts/preflight/compact_verifier_paired_20260909_v2_continued` 复制这 60 份回答与冻结输入，严格核对请求后复用，仅派发剩余最多 100 次。`scripts/resume_compact_verifier_trial.py` 仅对本地 persist 的 PermissionError 做短暂重试，不重试推理 POST，不改变提示词或选择规则。原批次账本、封存哈希和中断原因保留。

因此续跑的程序 panel_seconds 包含缓存重放，不可直接当作两组完整端到端速度。比较时按每目标每组 10 个请求中最慢一项的实测 elapsed_seconds 汇总，明确标为“重建的并行 API 时间”，不把恢复等待算作提示词耗时。

**完整 160 次配对调用完成，原始回答重放通过。结论：实测支持减少输入 Token，未证明四头识别更准或总费用更低，不升级默认流程。** 预设的严格通过结果为 false：4 对缺失提供方输入 Token，不能核实全部 80 对。其余预设检查通过，但 Phase 表面提升受接口失败影响，不能据此主张提示词质量提高。
