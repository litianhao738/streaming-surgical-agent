# Factored 审核说明长度：补充离线工程敏感性分析

本协议是在 Training 数字／名称配对结果及其 GT 已经分析之后、factored 付费实验仍运行时写下。此时已看到两条 factored HTTP 200 回答的 `observation` 分别为 1024、1296 字符，超过冻结 v3 Schema 的 1000 字符限制。这里没有查看尚未完成的 factored GT／分数。这是新增的补充工程敏感性分析，不能称作最初预注册的主实验。

原始 factored 请求、回答、严格校验失败及主结果全部保留。只有该 Training run 的 `summary.json` 完成标记、plan／prediction 哈希、全体目标和派发记录都验证一致后，才允许离线回放。Validation／Testing 不允许作为这个工具的输入。

统一规则仅适用于显式 `frame_label_presence_review_v3`：深拷贝回答，把每一个超过 1000 字符的 `observation` 字符串保留前 1000 字符。其他字段和值完全不改，包括 PRESENT／ABSENT／UNCLEAR、命题 ID、图片引用、范围和全帧检查声明。规则对全部回答统一应用，不按帧、GT、标签或预期分数选择。其他 Schema 错误仍然失败，不补字段、不改判决、不合成 UNCLEAR。

逐项审计原始及截断后文字长度和哈希。验证每个派发的 HTTP 状态、原生模型／供应商／请求 ID、请求及 wire 哈希、原 names 请求和拆分命题的对应关系。只有 HTTP 200 且身份、请求与内容绑定完整的回答才具备恢复资格。原有效回答保持相同判决；所有原错误同时重新校验，不能只挑两条已知失败恢复。

采用原 `merge_factored_presence_reviews` 和原 A/B：任一单命题仍缺失或非法时，整帧 review 仍然失败回退。保留全部 16 个 Training 目标及无变化／不可用候选。所有补充预测和变更审计先写入全新目录，之后才读取已完成主运行保存的 `scored_predictions.json`，关联同一批 GT 和逐任务 mask；不重新访问数据集标注，不选择或修改标签。

并列报告原始严格结果与长度规范化补充结果的五头 F1／集合 Accuracy、有效 GT 数、改对／改坏／无收益替换、有益／有害修改应用及恢复数量。严格结果必须可由原派发结果重放重现。新增 API 调用和费用均为 0，原实验费用不重新分摊。

恢复 JSON 格式不等于修复语义；即使补充分数改善，也必须明确其后验敏感性分析身份。是否在另一份明确冻结的 Validation 协议中采用该工程处理，由根任务另行决定；本协议及工具不修改任何在线入口。
