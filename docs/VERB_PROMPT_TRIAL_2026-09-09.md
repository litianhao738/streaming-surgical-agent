# 仅针对 Verb 的观察提示：固定候选池审核对照

日期：2026-09-09。独立入口 `scripts/run_verb_prompt_trial.py`；不修改当前默认 Pipeline 或历史最佳版本。

## 冻结设计

复用 `contact_first_candidate_20260909_v2` 的同一批 24 个 Training 目标、封存 H0 和 **control 原模板的候选池**。不复用 contact-first 的候选池，不调用新 H0 或补候选。样本已经评过分，属于开发集配对实验，不是新样本确认，不使用 Testing 选方案。

两组分别重新调用五席审核：control 使用原审核模板；verb_prompt 只追加 `verb_visual_audit`。两组目标顺序相同，逐目标交替先运行哪一组，每组内部五席并行。图片、候选池、其他输入、原评分要求、输出 Schema、长度上限和接纳阈值均固定。没有新反思轮次、额外模型、Tracker、Gate 或 Phase 审核。Phase 沿用同一 H0。

提示见 `src/surgical_agent/research/verification/prompts/verb_visual_audit_v1.json`：仅在审核 Verb 时检查当前器械接触状态与因果历史中的可见动作、区分相近动作；接触、握住、器械类型或阶段不自动证明额外动作；按已有类别边界判断；单处没有动作不足以否定整帧，证据不足按原规则给 UNCLEAR。没有新增动作定义，没有把多标签任务改成互斥类别，也不增加输出字段。此为同学观察思路的 Verb 专项适配，非其原文完整盲 H0 方法。

保留现有程序：五份有效评分才形成均分，新增 ≥4、删除 ≤2；新增 IVT 要求三个组件也通过。**因此只改 Verb 提示并不保证 IVT 或其他输出不变**：Verb 分数可能影响 IVT 接纳，联合审核的其他分数也可能受上下文或调用波动影响。本轮实际统计这些变化，不离线拼接最优头，也不按 GT 修改门槛。

五席沿用 Grok `grok-4.6`、Qwen `qwen3.8-flash`、GPT `openai/gpt-5.6-luna`、Gemini `google/gemini-3.5-flash-lite`、DeepSeek `deepseek/deepseek-v4-flash-vision-exp`。Grok/Qwen 走原直连，另外三席走原 OpenRouter 固定路由。原医学研究用途说明保持输入首字段。未更换模型或凭据。

最多 240 次 POST（24×2×5），空池跳过审核但保留目标。上限 OpenRouter $4、xAI $3、阿里云 ¥3；原生费用、估算与未知预留分别记录，不合并币种。无自动重试或补抽样。

预定成功要求：Verb Precision 高于本轮 control 且不低于 H0；Verb Recall/F1 不下降，其他头 Precision/F1 不下降，存在实际有益修改，无选择器失败，所有计划面板完成派发。报告全五头 Precision/Recall/F1/集合 Accuracy、有效 GT 数、逐项修正/新增错误、失败及费用时间。格式成功不等于有效语义票，也不等于修复成功。

调用前 4 项针对性测试和 Ruff 通过。冻结源文件、模板、全部请求指纹、原图哈希和缓存来源；推理使用仅媒体访问适配器，GT 只在推理封存并原始回答重放后进入独立评分命令。

## 结果

**本轮未通过预先固定的成功标准，不升级默认版本。** 新提示相对本轮原审核，Verb Precision 53.66% → 51.06%（−2.60 个百分点）；Verb F1 55.00% → 55.81%，IVT F1 24.39% → 26.19%。Instrument、Target、Phase 的逐目标输出完全相同。改善召回并不等于解决误报问题。

24 目标全部保留，23 个非空候选池各跑两组五席审核，另 1 个空池目标沿用 H0。共 **230 次真实 POST**，无重试或新增轮次。所有响应 HTTP 200；227 份直接解析、1 份按既有规则去除完整 Markdown 围栏后解析、2 份安全 JSON 解析拒绝。两次拒绝均为 control 的 Gemini（VID103/23751、VID31/21801），不能视为有效票。没有选择器异常。两组各 115 次调用，不重跑 H0 或补候选。

### 为什么没有兼顾

1. **提示没有稳定阻止把接触/抓持状态额外判成 grasp。** 相对 control，新提示多出两个正确 Verb、五个错误 Verb，并去掉一个错误 Verb；净 TP＋2、FP＋4。VID31/64826 的错误新增 `grasp`，均分从 3.6 上升至 4.2；Gemini 从 1 分变 5 分，GPT 仍给 UNCLEAR=3。新提示要求检查动作，但实际输出依然把观察到的抓持判断为额外 grasp，而该帧有效 GT 只有 retract。均分仍允许高分抵消不确定票。此处是模型输出与标注语义不一致，没有证据证明提示已经让模型完成正确视觉检查。

2. **只指定 Verb，并未隔离联合审核的 IVT 分数。** VID103/17126 的正确 IVT 17 均分由 4.2 降至 3.4，未被接纳；它的 Verb 仍保留，说明这次损失不是新代码强制连带删除，而是 IVT 自身评分发生变化。相反，VID23/34901 的错误 Verb 1 和 IVT 17 都从 3.0 升至 4.0，被一起放行。联合请求中的提示与模型调用波动均可能影响其他判断，不能声称 IVT 评分变化完全由文字内容造成。

3. **旧组件保护仍可能阻止删除错误 Verb。** VID23/19651 新提示下 Verb 1 均分为 1.8，本可删除；但 IVT 17 的 GPT 意见无效，整项没有有效均分，旧 IVT 被保留。Python 为保持该 IVT 的组件而留下 Verb 1。原审核中两项均分 1.6，因此都能删除。这是既有规则的可追溯行为，不是本轮新增代码改坏了选择器。

4. **一部分表面收益包含可用性差异。** VID103/23751 原审核 Gemini JSON 解析失败，新提示成功形成五票，新增了正确 Verb 0 和 IVT 7；不能把这全部归为视觉提示变好。另一个原审核解析失败目标 VID31/21801，新提示成功后反而新增错误 Verb 0。

主结果始终统计全部 24 个目标。另作事后可用性敏感性诊断：仅看两组都没有解析失败的 22 个目标，control → 新提示的 Verb Precision 为 54.05% → 51.22%，Verb F1 为 54.79% → 54.55%，IVT F1 为 24.00% → 23.68%。这不是替换主结果或重新选样，而是说明全体结果中的 IVT 增益不足以证明稳定的语义改善。详见 `transport_sensitivity.json`。

候选数量在两组完全固定：Instrument 37、Verb 52、Target 46、IVT 64 个命题。获得五份有效意见的命题数，control / 新提示分别为 I 33/37、V 42/50、T 32/34、IVT 35/45。意见合法率提高不等于正确率提高。无效逐候选意见为 81/49，归一化摘要显示 SCHEMA_INVALID，不能把所有这类意见都称为接口 JSON 失败。
