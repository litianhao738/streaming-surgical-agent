# 已确认的论文模块划分与消融设计

状态：用户已确认本设计，并要求同步至 GitHub。本次为设计文档同步，不修改默认运行逻辑、不训练模型、不执行新实验或 API 请求。当前主线仍运行已接入的完整方案 4；下面的无 Gate 对照尚需实现和验证。

## 模块定义

| 模块 | 内容 | 论文建议名称 |
|---|---|---|
| H0 | 初始 Instrument、Verb、Target、IVT、Phase 五头预测 | 初始预测 |
| G：Gate 模块 | 先验候选构建、Qwen 初审、学习型 Gate 决策 | 先验引导的选择性审核模块 |
| R：验证修复模块 | 后续交互审核、聚合、接纳/否决与歧义回滚 | 验证修复模块 |
| T：Tracker 模块 | M1 器械融合、M2 器械—动作先验、M3 因果阶段滤波 | Tracker 辅助时序修正模块 |

G 与 T 均为组合模块，不是单个模型。验证修复必须从 Gate 的模块定义中独立出来，以支持 H0＋仅验证修复基线。

完整方案的功能顺序为：H0 → G → 按决策跳过或执行 R → T → 最终五头输出。Gate 不放行时使用约定的 cheap 结果，再执行 T；不把跳过 R 解释为跳过整个最终输出过程。

## 第一个消融基线：H0＋仅验证修复

不能直接删掉当前代码的 Gate 前缀：候选池在该前缀内构建，Qwen 的初审回复又会被后续审核复用。无 G 路径必须保持 R 能独立运行：

1. 保留验证修复所需的通用候选提议，但不添加 G 的先验候选提示。
2. Qwen 回到普通审核席位，与其他审核员一起参与验证。删除的是选择性初审/路由功能，不是从审核阵容中删除 Qwen。
3. 不调用学习型 Gate；所有目标均进入验证修复。
4. 各组保持相同审核阵容、修复规则和早停策略。所有目标进入 R 不等于无条件调用完全部审核席位。
5. G 开启时，Qwen 初审回复由 R 复用，不再追加一次相同审核调用；费用统计不得重复计算。

这里 G 的先验作用首先指候选构建端的先验提示。实现时必须核对 cheap 构建、接纳/否决和回滚中已有的先验依赖，明确哪些是各组共同的 R 规则；不能只把学习型 Gate 固定为放行，就将其标作无 G。回退结果、候选生成和先验依赖需在运行协议中写清后再冻结实验。

## Tracker 内部消融与归因

T 可以包含 M1–M3，但仍需保留三者的分离消融：

- M1：器械融合与不兼容 IVT 过滤。
- M2：器械—动作先验；需区分动作规则本身与跟踪预测的贡献。
- M3：阶段滤波。它不依赖器械跟踪结果，是独立时序处理，不能将其收益称为跟踪器的独立收益。

无需为了结构对称而新增 Verber、Targeter 两个网络；但必须报告 verb、target 对照。若另行训练专用模型，则作为额外基线，不能与本次模块划分混为一谈。
