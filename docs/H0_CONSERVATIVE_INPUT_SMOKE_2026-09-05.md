# 保守精简输入：效果与费用对照

结论：本轮保守精简的实际费用下降 **1.57%**，但没有证明“降本不降质”。IVT、Target 的 micro-F1 上升，Instrument 下降，IVT 整组正确数下降。暂不替换默认基线。

## 实验范围

- OpenRouter `qwen/qwen3.8-max-0902`，严格 Alibaba 路由。
- 四个 Training 视频各两个目标，共 8 个目标、2 组、16 次调用；**16/16 成功，无重试、无未计价调用**。
- 原基线与保守精简均输入相同三张图 `[t-50,t-25,t]`，对应 `[-2,-1,0]` 秒，只预测最后一帧的五个任务。
- 两组均为 reasoning low、max_tokens 4096、temperature 0；历史图 low detail，目标图 high detail。
- 保留系统提示词中的完整 JSON Schema 和 API 的严格 response_format Schema，保留完整本体、标签边界和因果要求。
- 只删重复的 causal_frame_ids、空历史预测、空 track/workflow 状态及相关说明；保留 selected_image_frame_ids、相对时间、fps、本体版本、video_id、temporal_evidence 和目标帧要求。
- 没有运行 minimal，也没有运行之前会删除提示词 Schema 的 lean_low 方案。没有 Tracker、Repair 或跨窗口记忆。

总实付 **$0.207680**，低于 $0.35 的规划预算。没有本地完整响应缓存命中，且两组原始 usage 中服务端缓存读写也都为零，因此本轮费用差没有缓存折扣差异的干扰。

输入每次少 118 token，按本轮输入单价省 $0.000236；输出平均多 5 token，多花 $0.000030，净省 $0.000206。可见减少空文字只带来很小的总成本变化，保留 low 后思考消耗没有下降。

首个示例的系统提示词 6338 → 6118 字符，动态输入 578 → 299 字符，合计少约 7.2% 字符。这不等于 token 或账单同比下降。

如果只按本轮无缓存单价外推 15,282 个测试目标，原基线约 $199.93，保守精简约 $196.79，整套仅省约 **$3.15**。此前约 $184 的估算来自另一批存在部分服务端缓存命中的调用；不能将两个均价混用。这里均为外推，尚未实际跑完整测试集。

## 选择和验证限制

目标来自此前准备好的固定位置，未根据 GT 对错或预测置信度挑选：VID103 22951/36076，VID23 17326/28876，VID31 48751/77776，VID96 16676/25726。它们未参加此前完成的 32 目标付费预测，但此前中断研究曾对冻结目标运行离线 GT 评分，不能称为从未接触的新测试集。

本轮先冻结全部请求，再完成预测保存，最后读取 GT 评分。两组调用顺序交替，均使用新建本地缓存目录。temperature=0 也不代表生成完全确定；每种提示词在每个目标只调用一次，无法把所有预测差异都严格归因于文字删减。8 个目标不足以验证统计显著性或非劣效。

本次是帧集合 exact 和 micro-PRF，不是官方 mAP。IVT 包含 null 类 94–99。没有测试连续流每秒运行的吞吐，也没有验证完整测试集效果。
