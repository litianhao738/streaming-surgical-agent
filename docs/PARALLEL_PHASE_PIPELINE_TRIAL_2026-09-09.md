# 并行图谱修复＋Phase：真实费用和耗时

本次已实现并实际运行：**固定 H0 后，原图谱四头修复与独立 Phase 审核同时开始，最后统一合并五头。** 同一批 8 个 Training 目标共 88 次真实请求；推理实测 203.96 秒，平均 25.50 秒／目标。H0 复用缓存，不计作本次新生成。

实现入口：`scripts/run_parallel_phase_trial.py`；并行模块：`src/surgical_agent/research/verification/parallel_phase.py`；离线审核评分：`scripts/score_parallel_phase_trial.py`。

## 机制和保留条件

```
固定 H0 → 原图谱检索 → 单模型补候选 → 五模型四头审核 ─┐
同组三帧 → 五模型独立 Phase 单选／弃权 ──────────────┴→ Python 合并五头
```

- 图谱使用原 H0 和原初始候选池；不能用上轮修复答案作为第二轮输入，也不能把先返回的新 Phase 反灌图谱。
- 原图谱的提示、提案、五家审核及均分4接纳规则不变。Phase 保持独立三帧、七阶段定义、五份有效回答且至少三票一致的原规则。
- Phase 最终只更新新完成的图谱结果中的 `phase`，不会覆盖四头。图谱预期失败时回退 H0 四头；Phase 失败时只回退该阶段。
- 两路使用独立预算、停止标记和记录目录，防止 Phase 接口配置错误停止图谱支路。总体仍受分账户上限约束。
- 当前只实现并测试已有 H0 模式；每个目标两路并行、各审核内部五模型并行，目标之间仍顺序处理。没有加入 Tracker、Gate 或多轮，也没有合并模型请求。
- 缓存 JSON 被保存器排序后，H0 字段插入顺序会改变。新入口恢复原始顺序，使提案请求文本也与原实验完全一致；旧冻结文件不改。
