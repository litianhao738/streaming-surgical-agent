状态：80 次真实 API 请求完成，封存后独立回放及评分通过。**原图谱四头结果保持不变，Phase 从 5/8 提升到 6/8。两种历史组最终结果相同，暂保留较简单的短历史版作为开发候选。** 原冻结版本保留；本次不是全量 Testing 验证。

## 为什么上一轮五头版会降低其他头

上一轮并非只在原图谱 R1 上增加 Phase。`run_five_head_repair_trial.py` 让视觉模型完整重写五头；`five_head_repair.compile_joint()` 又把整个旧候选池纳入重新评分。旧候选因此得到新的接纳机会，修改范围不同于原版。

八个相同 Training 目标中，最终 Instrument、Verb 没下降；Target 多了一个错误标签、IVT 多了一个错误三元组。Target 错误来自旧池重新获准，甚至不是此次视觉修订提出的新增项。没有发生 Python 投影闭包强行添加组件的情形。

Phase 还存在两项机制限制：把当前是否正在夹闭等瞬时动作等同于工作阶段；七阶段逐项评分允许同一模型对互斥阶段同时高分。短三帧不足以解决所有阶段边界歧义，模型解释也有阶段定义误解。

## 结果和仍未解决的问题

本次两组相对原图谱 R1 都是：**改对 1 个、改坏 0 个、无收益替换 1 个、不变 6 个**。四头逐值不变是隔离修改范围带来的保证，不能声称四头视觉识别能力因此提升。

逐阶段诊断：

- VID96/15051：原 Phase 3，GT 1；短历史四票选择 1、长历史三票选择 1，均改对。审核解释开始区分胆囊颈／Calot 区域与肝床，但不能从这一个目标证明单选、盲审、类别说明各自贡献多少。
- VID23/28876：原 Phase 4，GT 5；两组改成 3，仍错。短历史四家解释为肝床分离；较长历史三家选 3、两家选 2，正确的 5 没有获票。说明多数模型仍会共同误认当前工作目的，互斥单选和合法 JSON 没有消除视觉错误。
- VID96/26051：原 Phase 3，GT 2；短历史三票 3、两票 1，没有选对。较长历史的 Qwen、Gemini 选 2，另外两家选 1、3，GPT 请求被拒；按预定规则保留 3。历史可能为个别模型提供了线索，但本次没有带来最终净收益，也不能断言补齐 GPT 就一定改对。

四个 GPT 请求收到提供方 `403 violence/graphic`，均明确注明 `No credits were charged`。短、长组分别有两个不完整面板，按规则回退；它们不是有效否定票。没有为通过筛查改变内容或重新调用。其余 76 请求 JSON 及单选协议有效。

两组结果相同，因此当前候选采用短历史；这也避免增加取更早图片的依赖。**还有两例 Phase 错误、IVT 集合 Accuracy 仍为零，不能称整个 Verifier／Repair 已完全解决。** 下一步应在新的 Training 目标确认冻结规则，不按这八帧 GT 加特判或反复改阈值。

## 本次修复和对照

```
固定 H0 → 原图谱辅助候选 → 原五模型四头审核 → 原 Python 局部修复
                                                      ↓
真实因果图片 → 独立五模型 Phase 单选／弃权 → 只更新 Phase
```

四头采用原图谱 R1 的缓存结果，逐目标逐列表保持相同。Phase 审核看图片与统一七阶段定义，不看 H0、旧 Phase、IVT、图谱统计或其他审核意见。每家模型只输出一个阶段或 null：

```json
{"phase_id": 1, "image_indices": [0, 1, 2], "observation": "Short description of current workflow evidence."}
```

`phase_id` 为 0–6 或 null；有阶段选择时必须引用当前图片；英文观察最多 1000 字符。五份响应均有效且至少三家选择同一阶段才采用，否则保留原 Phase。弃权不降低三票门槛。合法 JSON 和多数同意不能保证视觉正确。

两组共享规则、模型和目标，只改变 Phase 图片的时间跨度：

- `phase_short`：原始三帧，[-2,-1,0] 秒。
- `phase_context`：稀疏历史，[-30,-10,0] 秒。只在截至当前目标的连续可用段内取图；VID23/28876 只有 [-10,0] 两帧，其他七目标有三帧。

旧五头版与本次短历史版同时改变了审核范围、盲审、单选和阶段说明，不能把差异归因于一个因素。本次两历史组之间才是只改变时间跨度的对照。

阶段说明是基于本地七类映射的项目适配，不是官方完整边界标注手册。阶段名称对应一段工作过程，不要求名称对应动作每秒都出现。阶段 6 是经取物口取出，不能与普通牵拉混淆。参考 [EndoNet](https://arxiv.org/html/1602.03012) 的七阶段及时间建模背景、[CholecTrack20](https://arxiv.org/html/2312.07352v2) 的数据来源和采样协议。

## 冻结实验与复现

原始目录：`artifacts/preflight/phase_extension_eight_20260909_v1`。

- 固定八个已分析 Training 目标：VID103/18326、33576；VID23/13176、28876；VID31/40701、73701；VID96/15051、26051。
- 模型：Grok `grok-4.6`、Qwen `qwen3.8-flash`、GPT `openai/gpt-5.6-luna`、Gemini `google/gemini-3.5-flash-lite`、DeepSeek `deepseek/deepseek-v4-flash-vision-exp`；保持现有各家路由。Grok 无法关闭推理，并不把五席都声称为无推理模型。
- 两组共最多 80 次同步请求，五家在每个目标内并行，无 H0／候选新增调用、无自动重试；每次输出上限 4096 token。
- 开始前核查接口元数据及费用包络，账户上限 OpenRouter $2、xAI $2、阿里云 ¥2；它们不是预计实际账单。
- 先保存协议、源码及请求指纹，再执行推理；推理封存后单独载入 GT，按任务 mask 排除缺失标注。
- 独立回放原始请求与响应，重算票数及 TP/FP/FN/集合准确率，并断言四头逐值等于原版。
- 这八目标属于开发对照，不能用于声称全测试集提升；Testing 没有参与调参。
