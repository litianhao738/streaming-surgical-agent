# CholecTrack20 实际数据检查与方案建议

日期：2026-09-05。范围：本地媒体/标注/有效监督审计、现有实现审查、联网核查论文。没有新付费调用、模型训练或默认 Pipeline 改动。

## 建议结论

对当前以 API 为基础的项目，最适合立即验证的方案是：**单次联合五头 H0，6 张 1 fps 因果图像覆盖过去 5 秒，每秒预测一个目标帧**。以已有 **3 张 1 fps、跨度 2 秒**的 H0 作为对照，先不把修复器混入这次输入实验。

这是一项有依据、可落地的候选方案，尚未证明优于当前 H0。此前“25 张原帧构成一秒窗口，再抽三张”也没有被证明是最优参数。只有统一评测后的语义收益才能决定是否替换默认入口。

长期若目标是更可靠的手术语义识别，相关论文支持有监督的器械/组织空间识别和因果时序特征；但本地完整帧级 IVT 监督仅来自 4 个训练视频、覆盖 48/100 类，不能把现在直接训练一个 100 类模型当作可靠解决方案。需要先补足或明确限制监督覆盖，并审计外部手术数据与本测试划分的重叠。

## 实际检查到的数据

最终机器审计：[`track20_scheme_audit_20260905_v4.json`](../artifacts/preflight/track20_scheme_audit_20260905_v4.json)。SHA256：`826222ca466a3d7898981b067f7868ca3b209cc93207e817ca286ac4ac396dd0`。

同名前 v1/v2/v3 是保留的中间检查结果，引用以 v4 为准；尤其 v1/v2 将测试标注断点误当作视频历史缺失，v4 已纠正。

- 遍历 20 个视频的原始 JSON、训练/验证图片文件名和当前有效监督路由。原始共 35,009 个标注帧、65,247 个器械实例。
- Training：10 个视频，18,248 张 PNG；Validation：2 个视频，4,433 张 PNG。本地没有这些视频的原始 MP4。
- Testing：8 个 MP4，没有 PNG；视频头信息合计 505,290 个原始帧，全部 25 fps。标注索引无越界，各视频标注首/中/末位置共 24 次解码成功。此检查不是对全部原帧的完整解码或逐帧视觉标注核验。
- 官方明确原视频为 25 fps、标注为 1 fps，划分为 10/2/8；数据主要定位为检测/跟踪基准。项目的五头帧级语义评测需另行明确任务 mask 和聚合规则。[官方说明](https://github.com/CAMMA-public/cholectrack20)

按当前 parser、sidecar 与严格完整帧级 mask 统计：

| 有效监督帧 | Training | Validation | Testing |
|---|---:|---:|---:|
| Instrument | 17,963 | 4,430 | 15,282 |
| Verb | 7,787 | 1,713 | 6,631 |
| Target | 7,787 | 1,713 | 6,631 |
| IVT | 7,564 | 1,494 | 5,953 |
| Phase | 17,963 | 4,430 | 15,282 |

这里“有效”不是“图像存在”：原生实例标注聚合为完整帧标签时，要求非空且该任务的所有实例均有效。其他任务可继续使用自己的有效监督；不能把缺失任务当负标签。

重要限制：

1. **IVT 训练仅 4 个视频**：VID103、VID23、VID96，以及有显式 frame-level sidecar 的 VID31。仅实例监督为 7,317 个有效 IVT 实例，来自前三个视频；VID31 的 3,732 帧提供完整帧级多标签监督，不提供实例绑定/框/跟踪监督。
2. **IVT 验证仅 VID110**：VID30 当前候选修复源有 Instrument/Phase，有效 Verb/Target/IVT 帧均为 0。不能称为两个视频上的 IVT 验证。VID30 也不能表述为官方已经纠正的原生标签。
3. **类别覆盖不足**：把有效实例和 VID31 帧级监督一起计入，Training 也只覆盖 48/100 个 IVT 类。完整帧级正例统计中，48 类有 33 类不足 100 帧、20 类仅来自一个训练视频。Target 仅覆盖 13/15 类。保持完整本体；不能把未见类别从测试或预测候选池中静默删掉。
4. **PNG 存在时间缺口**：Training 有 351 个断点，Validation 有 104 个。按列表拿最近六张可能跨越缺口，不一定是连续六个 1 fps 时间点。
5. **测试 GT 不等于测试图片历史**：Testing 的完整 MP4 可以解码没有 GT 的历史时刻。不能因为历史标注缺失而重置视频图像缓冲。运行时 adapter 隐藏 Testing GT 是有意隔离，不能由 `evaluation=None` 得出官方没有标签。

可构造完整因果窗口且目标 IVT 有效的数量：

| 输入图像数（1 fps） | 端点跨度 | Training | Validation |
|---|---|---:|---:|
| 3 | 2 秒 | 7,376 | 1,432 |
| 6 | 5 秒 | 7,162 | 1,355 |
| 8 | 7 秒 | 7,049 | 1,307 |

这些是完整历史窗口的可用数量，不是正式评测可随意缩减的分母。正式推理应对开头/图片缺口采用预先声明的因果补齐或短窗策略，保留所有有效目标帧，并报告历史长度。

## 最相关的论文证据

| 方法 | 实际输入/建模 | 对本项目的含义 |
|---|---|---|
| RiT | 6 张 1 fps 图像，跨度 5 秒；训练时序注意力，预测末帧 I/V/T/IVT | 最接近当前严格因果目标帧任务；可作为 6 张窗口的起点，不能把训练网络的收益直接转移给 API |
| TargetFusionNet | 单帧器械实例分割和 IVT 监督，融合弱解剖特征 | 支持改善实例与靶点空间语义；需要 mask 等监督，Track20 的框不能直接替代完整模型所需标签 |
| Multi-task-attention video transformer | CholecT45-Vid 最佳为 16 帧@6 Hz，约 2.5 秒；稳定事件 clip 训练/评分 | 反驳“标注 1 fps 所以视觉输入 1 fps 必然最佳”；其 GT 延展与 clip 评分不等于本项目因果末帧任务 |
| TeCNO | 因果时序卷积处理历史视觉特征，监督 Phase | Phase 可需要更长历史；不能据此硬定 Track20 的最佳 30/60 秒窗口 |

RiT 五折实验中 RDV→RiT 的 Verb AP 为 62.0→64.0、IVT AP 为 29.4→29.7；整体 IVT 增益较小，grasp/retract/dissect 并未改善。它的 4/6/8 张消融属于另一划分，不能与上述主表混用。[RiT 原文](https://arxiv.org/html/2211.16963)

TargetFusionNet 在其自身数据集上，Mask2Former-Triplet→TargetFusionNet 的 IVT recognition mAP 为 32.28→34.23。它提供空间语义改进的实验证据，但没有时序或 Phase 模块。[论文](https://arxiv.org/html/2511.00643v1)、[官方代码及划分纠正](https://github.com/labdeeman7/target_fusion_net)

密集采样论文用稳定事件构造片段，并假设每秒标签可延展到该秒的 25 帧；不能照搬成 Track20 的稠密逐帧 GT。[原文](https://link.springer.com/article/10.1007/s11548-025-03546-3)。Phase 长历史的因果建模依据见 [TeCNO](https://arxiv.org/html/2003.10751)。

也检查了较新的 **TRCoRSurg（CVPR 2026）**：用最近 N=8 个视觉描述与预测 logits 的记忆、空间关系融合；论文内 CholecT45 IVT AP 为 40.9，比较方法为 38.9，即 +2.0 个百分点/约 +5.1% 相对提升。名称中的双向指时序与关系分支相互注意力，不能仅凭这个词判定它看未来。论文使用四张 H100 并承认训练复杂；这些结果不证明把记忆/关系模块接到同模型 API 修复链就有同样收益。[原文](https://arxiv.org/html/2608.04606v1)

**SurgMotion（早期版本名 UniSurg）**的官方代码提供 64 张@1 fps、步长一个采样帧、末帧预测的在线 Phase 输入实现。这是训练过的视频编码器路线，支持区分“采样”和“学习时序特征”；不是本地 8 GB GPU 应立即完整复现的依据。[官方代码](https://github.com/CAIR-HKISI/SurgMotion)、[论文](https://arxiv.org/abs/2602.05638)

此前的 StreamingVLM、Flash-VStream、M3-Agent、Vgent、TDC-Video、VideoARM 主要研究流式描述或长视频问答，并不为手术五头末帧分类提供直接参数最优性证据。它们也不全是把图像发送给 API：例如 StreamingVLM 训练模型并维护 KV；VideoARM 则确实使用 API 和时间定位工具。[StreamingVLM](https://arxiv.org/html/2510.09608v1)、[VideoARM](https://arxiv.org/html/2512.12360v2)。其余逐篇依据保存在此前的 [streaming 论文笔记](../artifacts/preflight/window_density_streaming_papers_20260905.md) 与 [memory 论文笔记](../artifacts/preflight/window_density_memory_papers_20260905.md)。

## 具体采用什么输入和步长

把采样率、历史跨度、输出步长分开定义。以下 t 是原视频帧号，原视频 25 fps：

```text
推荐验证候选：
[t-125, t-100, t-75, t-50, t-25, t]
                 ↓
一次 API 联合输出目标 t 的 Instrument / Verb / Target / IVT / Phase

下一个目标 t+25：
[t-100, t-75, t-50, t-25, t, t+25]
```

- 图像按旧到新排列，附真实相对时间 -5/-4/-3/-2/-1/0 秒，所有输入不晚于目标。
- **步长为一个 1 fps 采样点，即 25 个原始帧；不是 25 个采样点，也不是每个窗口互不重叠。** 相邻正常窗口共享五张历史图像。
- 每个调用仍独立做联合五头预测；复用图像缓冲本身不等于跨窗语义记忆，也不证明服务器模型已经利用运动。
- PNG 输入缺口必须记录并按既定策略处理；MP4 历史按帧号解码，历史时刻无需 GT。
- 当前正式 factory 硬限三图，修改实验窗口不会自动改变正式 Pipeline；候选应在独立入口验证。
- 当前 API 的实测调用通常需要约 25 秒，**1 Hz 指目标采样/输出索引密度，不代表一秒内返回结果的实时系统**。

## 下一项最小验证与预算（尚未执行）

建议先固定 VID110 上 60 个具有完整 6 张历史且 IVT mask 有效的目标，其他头仍使用各自 mask，按时间均匀选取。预测前只用帧号、媒体可用性和任务 mask，不用标签类别/模型错误挑点。三组共享相同目标、提示和推理设置：

1. 当前三张：`[t-50,t-25,t]`。
2. 六张历史：`[t-125,t-100,t-75,t-50,t-25,t]`。
3. 六张当前帧重复，所有实际时间均为 t，作为“没有历史信息”的诊断对照。

共 **180 次 API 调用**。依照先前实测成本粗估约 **3–5 美元，预设硬预算 5 美元**；这不是供应商报价保证，实际价格和首批调用费用须在执行时核对，预算不足则停止并明确未完成配对，不静默缩小分母。本轮没有发起这些调用。

这轮只能检验输入方案的整体差异，以及历史内容是否有增益；不能单独分离图像张数与跨度效应，也不能由它证明时间顺序的因果作用。若六张历史有收益，再做固定末帧的历史顺序/时间映射诊断。

评分保留每头完整集合正确率、micro-Precision/Recall/F1、失败率、调用成本和耗时，重点看 Verb/Target/IVT 的真实改善。对局部片段分别汇总，不能把 60 个相关时间点当 60 个独立视频。API 若仅给标签集合，就不能把硬标签得到的退化 AP 当作与论文连续类别分数的 mAP 可直接比较。

既有 25 帧密度冒烟也不能替代此验证：VID06 六个目标上，一秒内三张与全 25 张的 IVT micro-F1 为 50% 与 48%，全 25 张费用约为三张的 2.54 倍。它只说明那六个目标没有观察到增加密度的 IVT 收益。[已完成评分](../artifacts/preflight/window_density_h0_qwen0902_vid06_20260905_scored/summary.json)

## 若 API 仍不改善，训练什么

先核验并增加不与 Track20 验证/测试重叠的手术动作监督，或明确把训练实验限制为已有覆盖类别的适配，同时仍按完整约定本体报告结果。官方明确 Track20 与 Cholec80/CholecT50 重叠；外部手术预训练权重也需查来源，不能只核查微调划分。[官方重叠说明](https://github.com/CAMMA-public/cholectrack20#potential-overlap)

随后最小训练基线可复用现有 MobileNetV3→单向 GRU→五头代码，从普通图像预训练初始化，用有效末帧五头标签学习视觉特征、短时序和分类头，比较单帧/三帧/六帧。训练的目的，是用标注约束器械、动作和组织的视觉决策，而不是训练“同意修复”的话术。缺失任务须 mask；类别长尾和未见类必须单列。当前 GPU 为 RTX 4060 Laptop 8 GB，可先做轻量模型的显存探测，不能直接承诺原论文配置可运行。

空间改动应作为下一项独立消融：利用有效训练器械框和实例 IVT 学习器械区域及周围组织的关系，保留全图解剖上下文。部署结果必须使用预测框；GT 框只能作为明确标注的定位上界诊断。Track20 没有本次核实到的 TargetFusionNet 所需实例 mask，不能称为该模型复现。

Phase 长历史只在单独验证后再加。不要同时换骨干、加 ROI、改时序、加 Phase 记忆和启用 Repair，否则不能识别收益来源。

现有本地 checkpoint 只有一个 optimizer step、实际验证两帧，仅证明训练工程可运行。`--mode full` 会启用 ImageNet 初始化，默认 smoke 不启用；正式 API factory 尚未接入本地 checkpoint。详见 [实现检查](../artifacts/preflight/track20_implementation_readiness_20260905.md)。

## 测试评估约定

冻结输入策略、模型、阈值和评测规则后，在 Testing 原视频上因果解码；只在对应任务有有效 GT 的原生标注目标评分。不得把每秒 GT 插值成 25 fps 真值。所有方法使用相同目标和每头 mask，模型失败也计入约定分母。

由于有效 IVT 验证实际上只有一个视频，还应在四个有动作监督的 Training 视频内做视频级开发验证/留一视频检查，避免按随机帧划分产生相邻画面泄漏。VID110 上已经反复诊断，Testing 的 VID06 也参与过密度诊断；正式结果应披露这些使用历史。

本轮新增离线审计与报告，不替换已有实现和冻结实验。结构闭包、输出合法、模型自述证据充分均不是语义识别改善的判据。
