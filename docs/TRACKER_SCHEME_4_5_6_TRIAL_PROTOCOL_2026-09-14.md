# 方案 4、5、6 顺序试验协议

用户要求先试方案 4，再试 5 和 6。本协议先于本轮新实现的结果计算。

## 方案 4：零 API 独立研究版本

1. 不改默认、旧脚本、旧数据和旧模型。三个既有 v2 探针通过仅重定向输出路径的副本执行，网络禁用；与已保存 JSON 比较。
2. 实现独立 action=0/1 运行时：原 H0、proposal、Qwen、42 特征、交互审核、精确早停和歧义回滚保持语义一致，不执行阶段推荐/阶段审核。
3. M1 使用冻结当前帧 score>=0.35 的器械集合，替换 instrument 并过滤器械不在集合中的 IVT。缺失/不可用/不合法 Tracker 回退该模块；正常空检测允许输出空 instrument/IVT。器械超原 schema 上限时整个 M1 回退，不任意截断。
4. M2 冻结 clipper→clip、hook→dissect、scissors→cut 三条规则，只在当前有效 Tracker 融合器械上追加动作。动作超 schema 上限时仅回退 M2。Tracker 不可用或 M1 回退时不应用 M2。先验来自此前开发，不能称为独立发现。
5. M3 对 cheap 的原始阶段进行因果众数滤波，使用 (t-W,t] 秒内的可用原始输出；不插值、不递归反馈滤波结果。任何最高计数平局都保留当前原始阶段。每个视频独立状态，拒绝时间倒退/重复输入。该定义修正文档和旧探针的差异，因此不强求成绩等于旧数字。
6. 固定网格 W∈{0,5,10,20,30,60}；外层视频的窗口只由其他视频选择，平分选较短窗口；全量开发选择的固定窗口另列。所有默认/对照的滤波设置在消融中保持一致。
7. 先验证旧 Gate 路由下 M1–M4；再训练相同 42 维 HGB 的 Gate v2，标签为 M1+M2 后交互四头的 review/cheap 是否不同。嵌套按视频拟合，5%–100% 内层阈值网格，选择满足 90% 审核 F1 增益、总体错漏不增和逐视频不差的最低调用候选。固定规则不在每折重新用 GT 搜索。全量模型、外层结果和全量模型训练集回放分开存储。
8. 逐帧验证原输出/特征/调用路径等价性与最终 schema，记录 IVT 删除 TP/FP、器械/动作容量回退、逐头/逐视频结果、阶段切换观测延迟及稀疏采样限制；补齐 Tracker×PGP×Phase 消融。
9. 四个反复用于开发的 Training 视频不构成独立验证；既有上游先验与 Tracker 未完全嵌套。默认不自动晋升。

## 方案 5 和 6：在方案 4 后独立配对

- 方案 5 只将先验候选检索的允许器械集合从 H0 扩为 H0∪当前 Tracker；不把 Tracker 写入 H0，不直接写入最终 IVT，不提高现有两个提示/四个新 IVT 的容量。保持原 proposal 和审核流程。
- 方案 6 保持原候选池，只在原 Qwen compact 请求中加入已定义的两项 Tracker 提示字段；其余审核请求不加。不能把旧 Qwen 输出充当新提示输出。
- 每个方案各有相同输入的对照。采样只依赖视频/时间和预测，不使用新的精度结果；不只采旧 Gate 放行帧，以便评价路由变化。先做小规模 Training 配对，不访问 VID110/Testing。
- 主要比较方案 4 后处理之上的增益，同时报告原始输出、候选覆盖、调用和各账户成本。更改输入后，旧 Gate 只作迁移对照，不宣称旧模型保证仍成立；不足以重训时不以小样本重训结果替代验证。
- 准备阶段不调用 API。先产出样本、请求差异、调用上限和账户预算计划，再由用户确认付费采集范围。两项先分开，不能用组合结果冒充各自作用。
