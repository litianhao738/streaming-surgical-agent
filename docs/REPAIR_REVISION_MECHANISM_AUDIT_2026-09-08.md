# Verifier / Repair 机制审查：哪些是代码问题，哪些是模型判断问题

日期：2026-09-08。初始范围：旧 12 个 Training 目标及其已保存的三轮回答、格式修复离线重放；后续补充开发批 8 目标的完整缓存重放，以及确认批截至第二轮的有害编辑诊断。本审查不调用 API、不使用 Testing，不修改冻结推理源码。确认批的中间诊断不代表其最终结果。

发布时补充：本文保留问题发现时的机制记录，其中“没有回传观察”针对旧单提案分支；后来新增的具体观察反馈分支已完成四目标对照，见[当前发布指南](VERIFIED_REPAIR_CANDIDATE_2026-09-08.md)和[完整结果](REPAIR_REVISION_RESULTS_2026-09-08.md)。本页 `artifacts/...` 为未公开的本机历史证据位置。

## 先说结论

历史实验暴露了可修的工程问题：多余字段和 JSON 外的 Markdown 符号使合法核心判断被丢弃；旧 12 目标实验还把一个空候选池误标为通过。该空池问题已在后续代码修正。本次新 runner 的边界检查也已修正：非法或缺失提案、最后一轮才提出的未审核建议、容量限制丢弃的建议都不能形成 `MODEL_PASS`。本文件不声称当前冻结 runner 仍存在这些已修复的误标。

但更关键的语义问题仍存在：模型会给错误关系高分，也会漏掉正确关系。**输出格式正确、五个模型同意、循环次数更多，都不等于视觉答案正确。**

候选生成也并非没有作用：H0 只覆盖 3/19 个真实 IVT，候选池最后覆盖 10/19。瓶颈同时包括“正确关系根本没有进入池”和“进入池后没有被可靠选中”。

## 现在的接纳机制，用白话讲

1. H0 看三张因果图片，输出 I、V、T、IVT、Phase 五头的最终标签，没有 top-k 或模型置信度。
2. 提案模型补充候选；把一个 IVT 放进候选池时，程序也加入它需要的器械、动作、目标候选。**加入候选池不等于加入最终答案。**
3. 五个审核模型分别看同样图片，对每个候选给 1–5 分、支持/反驳/不确定、证据所在图片及局部/整帧范围。
4. 五席这一项都合法才计算均分。均分 ≥4 支持存在，≤2 支持不存在，中间保留当前状态。Phase 保持 H0。
5. 新增 IVT 还需要 I/V/T 三个组件分别通过；独立 I/V/T 标签目前也可以只凭自身高分新增。删除组件时，若仍有保留 IVT 需要它，就不能删。
6. 有未解决候选就继续，最多三轮。下一轮使用的仍是原来三张图。

对应代码：[recent_mean_panel.py](../src/surgical_agent/research/verification/recent_mean_panel.py)、[semantic_coordinator.py](../src/surgical_agent/research/verification/semantic_coordinator.py)、[candidate_coordinator.py](../src/surgical_agent/research/verification/candidate_coordinator.py)。

## 已核实的具体问题

| 问题 | 实际事实 | 应如何理解 |
|---|---|---|
| 格式过于脆弱 | 103 项 `SCHEMA_INVALID` 全部来自 Gemini；94 项含额外字段，另 9 项来自一次完整 JSON 后多出尾部 Markdown 围栏造成的整次解析失败 | 属于工程问题，可以安全规范化外层格式和一致的辅助字段；不能猜补缺失标签或改写核心判断 |
| 一席无效会挡住整项 | 五席中任意一席证据无效，该候选均分就是空值 | 会放大格式失败的影响；但改成少数有效票通过也可能放行更多错误，不能自动视为优化 |
| 局部否定不能支持整帧删除 | 原记录另有 155 项 `LOCAL_ABSENCE_CANNOT_DELETE_FRAME_LABEL` | 一把器械没有某动作，不代表全帧所有器械都没有；该约束有真实语义理由 |
| 分数与判断冲突 | 另有 3 项 `RATING_FINDING_CONFLICT` | 例如“看不清”却给支持分，应继续拒绝，不通过填默认分修复 |
| 高均分不保证正确 | 第三轮原池中 10 个真 IVT 有 8 项无法均分、2 项不确定；达到均分 4 的 5 个 IVT 全是假项 | 既有正确项被挡住，也有模型共同误判；不是单纯降低门槛即可解决 |
| 独立组件修改扩大了损伤 | I/V/T 可以脱离任何已通过 IVT 单独新增 | 可能只增加一个错误动作或错误组织，没有形成更准确的器械—动作—目标关系 |
| 循环通过条件偏严格 | 未选中的备选项也必须低分反驳，否则继续未解决 | 可以因一个一直看不清的备选反复调用；“没有解决”不等于“必须继续获得同样回答” |

额外字段包括 `image_indices_string`、`scope_notes`、`scope_correction`、`scope_status`、`observation_token_count`、`scope_validated`，以及值为空的嵌套候选键。已观察到的非空 scope 辅助值与核心 scope 一致，图片索引字符串也与核心索引一致。不同值、候选绑定冲突、重复键、缺失核心字段仍应拒绝。

目前的均分规则**不以模型间冲突作为否决条件**。例如 `[5,5,5,5,1]` 的均分为 4.2，即使一席明确反驳，也可能通过。`explicit_conflict` 只是记录字段。这是当前策略选择，不是算错平均数；是否改成冲突否决，需要单独对照。

## 英文、宽格式、组件限制分别能解决什么

**英文已经在用。**旧记录中可读取的 1,511 段观察文字未出现中文，实际提示、类别名和观察主要使用英文。之前向用户展示的中文 JSON 是解释性示例。更换语言没有证据能解决当前问题。

**宽格式只解决解析，不证明更会看图。**对原 103 项 Schema 失败进行规范化，89 项恢复为合法核心判断；5 项去掉额外字段后仍因局部否定不足被拒绝；尾部围栏造成的另 9 项中恢复 8 项，剩余 1 项也因局部否定不足被拒绝。合计恢复 **97/103** 项，不是全部恢复。恢复成合法判断不能记为“改对了标签”。格式重放的第三轮 IVT F1 为 20.51%，原规则为 21.05%，没有语义提升。

**目前没有证据表明组件门槛是主要瓶颈。**对格式修复后的三轮逐项核查，所有“本轮想新增且 IVT 自身均分已达到 4”的项目中，被额外 I/V/T 组件门槛挡住的数量均为 0。也就是说，直接取消组件要求不会在这批记录里释放出被它挡住的正确 IVT。更多真 IVT 没有通过自身审核，或者根本未进入候选池。

局部否定还有一处值得区分：当前校验在计算均分前执行，所以即便候选本来不在当前答案里，一份局部低分也会被判无效。它能阻止无依据的整帧删除，但同时会让一个仅仅“暂不新增”的备选持续未解决。未来可以区分“不能作为删除证据”和“没有支持新增”，不能直接把局部低分当成整帧不存在。

## 循环有没有积累更多真证据

| 阶段 | 真实 IVT 覆盖 | 本轮新增真 IVT 候选 | 本轮新增假 IVT 候选 |
|---|---:|---:|---:|
| H0 | 3/19 | — | — |
| 第一轮候选池 | 7/19 | 4 | 12 |
| 第二轮候选池 | 10/19 | 3 | 1 |
| 第三轮候选池 | 10/19 | 0 | 2 |

第三轮最终增加了 2 个错误标签，没有增加正确标签。这是这批样本的事实，不能据此按 GT 决定每帧停止时机。

模型每轮重新观察相同的三张图，**没有获得新的时间段、近景或外部定位证据**。第二轮确实找到更多真实候选，说明重看可以补漏；但它是重新解释已有证据，不是获取新的独立证据。后续模型也可能被已经扩大的候选池影响，因此多轮不能当成独立投票次数叠加。

## 最小的下一候选：只应用有完整关系支持的新增组件

建议先离线检查一种受限 Repair：**当前已有标签保留；新增 IVT 的评分与组件门槛不变；本轮新增 I/V/T 只有在某个本轮已接纳的新 IVT 确实需要它时才加入。**其他单独高分组件暂不修改。删除规则、五席要求、阈值和轮数都不变。

例如，一个 Target 获得高分，但所有使用这个 Target 的新 IVT 都没有通过，就先不把这个 Target 加进最终答案。这样缩小修复影响范围，不假定 H0 的独立头必须完全等于 IVT 投影，也不会重建或删除 H0 原有的独立标签。

已对旧回答完成零调用的单步影子检查：每一轮都使用该轮原始的修改前状态与已保存审核结果，仅改变上述新增组件规则。

| 影子检查 | 阻止的错误新增 | 阻止的正确新增 | IVT 是否变化 |
|---|---:|---:|---|
| 第一轮 | 2：1 个 Verb、1 个 Target | 0 | 不变 |
| 第二轮 | 2 个 Verb | 0 | 不变 |
| 第三轮 | 1 个 Target | 0 | 不变 |

第三轮单步 Target F1 从格式修复的 47.06% 到 48.48%，仍低于 H0 的 50%；IVT F1 仍为 20.51%。**这是减少局部误改的线索，不是成功的端到端修复结果。**三轮不能把收益相加：各轮沿用不同的原始前态，提案也没有根据新方案重新生成。闭环效果必须使用固定方案在新 Training 目标上验证。

该方案的局限是不能解决候选共同漏检，也可能挡住未来样本中正确但未形成 IVT 的独立组件。因此只作为下一候选，不自动替换当前实验或将其写成已证明优化。

为避免把单步影子检查误称为闭环，另准备了本地历史工具 `tools/audit/replay_component_limited_repair.py`（该未采纳对照工具不在本次候选发布范围）。分布式审核请求只依赖候选池、图像、帧号、本体和固定模型设置，不读取当前答案或上轮问题；因此可以从 H0 开始运行受限策略，逐轮检查请求是否与缓存完全一致。脚本先复现原策略，再核对新策略的候选池、五席响应来源哈希和停止分支。若新策略需要原实验没有执行的下一轮，或请求发生变化，就明确标记不完整，不能补造响应、挑可重放的好样本算分。

已用两个分布式审核完成的目标做运行中工程自检，2/2 通过原策略复现与请求核对，新增调用为 0，未读取 GT 算分。该自检不是新 8 目标的效果结果。完整批次结束后，还须对全部预选目标完成重放，才能单独调用评分程序。这类结果应称为“请求完全一致的缓存策略重放”，不是独立模型抽样；脚本也不把账户全局调度和预算停止模拟成已验证事实。

## 补充审查：下一轮到底收到什么反馈

**事实：单提案链路没有把审核者的视觉观察传给下一轮提案模型。**[recent_mean_panel.py 第 70–81 行](../src/surgical_agent/research/verification/recent_mean_panel.py#L70)生成的每项 `issues` 只有 `candidate_id`、`currently_selected`、`mean`、`scores`、`invalid`。没有 `observation`、`image_indices`、`finding` 或 `scope`。

[proposal_body 第 56–69 行](../scripts/run_candidate_panel_trial.py#L56)将当前答案、候选池和这份 `issues` 放进请求；[gemini_proposal 第 84–90 行](../scripts/run_semantic_candidate_trial.py#L84)仅补充类别边界、模型和路由设置，没有追加审核观察。已核对真实第二轮请求 `artifacts/preflight/recent_mean_panel_20260908_v2/calls/078_VID103_12501_proposal_2_base/request.json`：其中 7 项问题确实只有上述五个字段。完整审核文字保存在实验记录里，**被保存不代表进入了下一轮输入**。

提案输出也明确受限：只能返回 Instrument、Verb、Target、IVT 四个候选 ID 列表；提示要求只补池内尚无的新候选，不允许直接接纳、删除或改变最终答案。因此它不是一个能输出“删除错误关系 A、加入关系 B、说明如何验证”之类纠错组的 LLM Repair。最终修改仍由 Python 按五席审核结果执行。分布式提案臂更不读取 `current` 或 `issues`，每轮只看图片和候选池重新审核、补候选。

**推断与局限：**单提案模型知道“哪一项分歧较大、哪些票失效”，却不知道“谁认为器械没有接触、谁看到了牵拉、各人引用哪张图”。这可能让后续提案缺少具体纠错线索；而只许补新 ID，也限制了它对已有错误候选提出针对性纠正的方式。上述是已核实的设计限制，**尚未证明是当前低 IVT 的主要原因**。模型仍然能重新看图找到新关系；审核者的观察本身也可能错误，转述这些观察可能增加锚定和共同误判。

最小可验证方案是**只增加传给提案模型的有效视觉反馈**：

1. 两组共享相同 H0、第一轮提案、第一轮五席审核及第一轮修改后状态。只比较按原规则确实需要第二轮的目标，资格不看 GT。
2. 对照组第二轮仍发送原 `issues`；试验组在同一份问题列表下，额外附上各有效审核项的 `rating`、`finding`、`scope`、`image_indices`、`observation` 与固定审核席标识。保留分歧原貌；无效项只保留原失败原因，不猜补其视觉判断，不把审核者文字当成真值。
3. 提案模型、三张图片、完整本体、输出 Schema、只能补新 ID 的权限和候选上限都不变。随后仍由同样五个模型独立看图审核；它们不接收新增反馈，也不接收其他审核者的回答。均分、组件约束、删除规则和接纳阈值不变。
4. 固定比较第二轮结果，不根据中途 GT 分数决定是否继续。每个实验臂第二轮仍是 **1 次提案 + 5 次审核**。共享首轮以后，两个臂合计最多新增 12 次调用/目标；反馈文字可能增加输入 Token，需单列实际费用，不能声称费用不变。
5. 完成并保存推理后，再比较新增候选中的真/假标签、真实 IVT 覆盖、五头 Precision/Recall/F1/集合 Accuracy、改对/改坏/无收益修改，以及解析失败和新增费用。

这只检验“更具体的反馈能否帮助补出更好的候选”，不能同时证明 LLM 直接修复已有答案有效。若提案和最终语义指标没有改善，就保留原方案；不通过同时降低阈值、扩大候选池或增加轮数制造难以归因的结果。本补充未新增核心模块、未调用 API，也没有使用正在运行的确认批 GT 设计方案。

## 后续验证与强冲突诊断

**受限新增组件方案已被新开发数据否定。**开发批 8 个目标现已完成原策略逐轮复现和受限策略的完整缓存重放，所有请求、候选池及停止分支均可复用。受限策略的 8 份最终答案全部等于 H0，总标签错误为 58；原分布式方案为 54。Instrument F1 从原分布式的 84.62% 回到 75%，Target F1 从 50% 回到 36.36%，IVT F1 均为 16.67%。受限方案复用 100 个审核响应，没有减少原审核调用，因此不应采纳。见[完整重放与评分](../artifacts/research/verifier_repair_revision_20260908/component_limited_complete_v1/scores/report.json)。前面的旧 12 目标单步影子结果仅解释了为什么提出这个候选，不能替代新数据验证。

另对确认批第二轮已保存的有害修改检查了“强正反冲突是否被平均掉”。单提案臂的 1 个有害 Target 新增，五席为 `[4,1,5,5,5]`，均分 4；低分席是合法的整帧 `REFUTED`，其余席为 `MATCH`。恢复旧强冲突否决，能在该原始前态的单步影子检查中挡住此项。

但分布式臂的 9 个有害标签编辑均没有强正反冲突：错误新增得到五席 `MATCH`，均分为 4.4–5；错误删除的器械、动作、IVT 则全部得到 `[1,1,1,1,1]`、`REFUTED`、`WHOLE_FRAME`，并引用当前帧。旧冲突否决对这 9 项全部无效。**合法整帧否定与五席一致，仍然可能在语义上共同出错。**

同一条强冲突否决也有代价：开发批单提案的 5 个有益新增中会挡住 1 个；开发批分布式的 4 个有益新增中会挡住 2 个。两臂分别计数，不将重叠样本相加当成独立证据。因此这里仅做机制诊断，不根据确认批的一项可阻止错误选择新规则，也不把逐项影子结果写成完整闭环效果。原始五席分数、判断、范围及观察见[强冲突影子诊断](../artifacts/research/verifier_repair_revision_20260908/strong_conflict_shadow_v1.json)。
