**1. 项目整体流程**

本项目计划让系统连续分析手术视频：先判断当前画面中的器械、动作、操作对象、组合关系和手术阶段；再判断是否值得调用同一个大模型进行一次额外复核。目标是在提高结果可靠性的同时，控制额外调用的次数、时间和费用。

```text
读取当前帧和此前帧
        ↓
整理图像、标注、数据划分和有效标签
        ↓
提取器械轨迹，并总结此前已经发生的手术流程
        ↓
大模型进行第一次判断，给出初始结果和候选答案
        ↓
决策模块选择：直接接受，或进行额外复核
        ↓
得到最终结果，更新流程记录和历史记忆，再处理下一帧
```

计划中的主要模块包括数据处理、器械跟踪、手术流程状态、大模型初始判断、复核决策、证据化复核、历史记忆、训练和评估。目前真正实现并经过测试的主要是基础配置和数据处理部分。其余大部分模块只有目录、接口或占位文件，尚未形成可端到端运行的系统。

**2. 经核查后确认的现有问题**

1. **`VID30/VID31` 数据关系异常：已形成独立的派生使用方案**  
   `VID30` 的 1,863 条核心实例标注与 `VID17` 相同；`VID30` 的图片编号集合又与 `VID31` 的标注编号集合完全一致。Cholec80 逐图验证确认了两个视频的媒体身份和时间偏移，CholecT50 又为 VID31 提供了可核验的帧级 Instrument/Verb/Target/Triplet presence。项目不覆盖原始 JSON，而是在原 VID 目录内显式加入侧车标注：VID30 作为候选修复验证数据，VID31 使用 CholecT50 帧级 I/V/T/Triplet presence 与 Cholec80 phase，不使用实例、bbox、operator 或 track supervision。

2. **测试视频的帧编号规则：工程上已经解决，官方文字仍不完整**  
   全部 Track20 标注编号都满足固定的 25 帧间隔规律，并通过本地边界检查和上游同源帧规律交叉验证。项目已冻结“标注编号减 1，对应视频解码帧编号”的规则；它足以支持代码运行，但不应写成维护者明确发布的原文。

3. **手术阶段映射：实际含义已获高可信支持，但来源记录尚未收口**  
   Track20 官方发布没有提供单独的“阶段编号到名称”表。不过，CholecT50 的官方映射和 Track20 本地动作分布共同支持：编号 2 是“夹闭与切割”，编号 3 是“胆囊分离”，其余编号也与上游映射一致。当前真正的问题是：这项跨数据集验证结果尚未同步到数据配置和正式映射文件，正式实验还需要保存来源、版本和验证方法。

4. **负数标签和少量组合冲突：数值现象已证实，完整语义仍不明确**  
   数据中确实存在 `-1` 和 `triplet=-2`。其中 `triplet=-2` 共 1,129 条，1,116 条与 specimen-bag 有关；这与上游 CholecT50 没有 specimen-bag 组合类别相吻合，但不能据此断言 `-2` 的官方定义。34 条组合关系冲突中，32 条可以用“Track20 标的是袋子，而上游组合描述的是抓袋子的器械”作合理解释，但该解释并非官方确认；剩余 2 条仍没有一致解释。
。

**3. 这些问题对项目实现的实际影响**

1. **对应问题 1**：原始 `VID30/VID31` JSON 仍不能直接进入训练或评估。显式加载 `repair_manifest.json` 后，VID30 可作为候选修复验证集；VID31 可提供 CholecT50 帧级 Instrument/Verb/Target/Triplet presence 与 Cholec80 phase，其检测框、实例配对、operator 和跟踪字段继续屏蔽。

2. **对应问题 2**：帧规则已作为带证据版本的配置投入使用。运行时仍须禁止最近帧回退或自动搜索偏移，避免不同实验得到不同帧。

3. **对应问题 3**：高可信阶段映射足以支持继续实现数值标签读取和小规模验证，但语义名称、阶段统计和论文报告必须记录其跨数据集来源。这里主要影响可追溯性，不再构成“阶段任务完全不能实现”的绝对阻塞。

4. **对应问题 4**：当前采用“负数标签在对应任务中不参与训练和评估”是保守且可执行的做法，但它只表示标签不可用于监督，并不等于已经解释了这些负数的医学含义。不同任务必须分别判断标签是否有效。

这些影响具有先后关系：先确认数据和帧对应，才能可信地评估第一次判断；先证明额外复核本身有效，才有必要训练“何时复核”；只有最终结果定义稳定，历史记忆才不会持续保存错误状态。

**4. 对应的解决办法和调整建议**

1. **对应问题 1：使用派生监督清单**  
   保持原始文件不变。VID30 使用原图片、VID31 JSON 核心字段和 Cholec80 video30 phase 构成候选验证源；VID31 使用原图片、Cholec80 video31 phase 和 CholecT50 帧级 Instrument/Verb/Target/Triplet presence，实例、bbox、operator 和 track supervision 全部关闭。每个来源、偏移、哈希和字段开关都记录在 `D:\cholec_dataset\repair_manifest.json`。

2. **对应问题 2：把帧对齐作为带证据的配置**  
   编写独立检查工具，利用可获得的同源视频逐帧比较候选规则。配置中同时保存规则、适用视频、验证方法和证据版本；未通过检查的视频应停止处理并报告，不能自动选择最近帧。

3. **对应问题 3：更新阶段映射及来源记录**  
   把高可信映射写入独立的版本化映射文件，同时标注“上游官方映射 + Track20 本地语义分布验证”，不要标成“Track20 官方显式表格”。随后同步数据配置、审计报告和测试，避免不同文件继续给出互相矛盾的状态。

4. **对应问题 4：继续使用逐任务有效标记**  
   保留全部原始编号；器械、动作、对象、组合关系和阶段分别决定该标签能否参与训练。报告每种被排除标签的数量和来源，不把 `-1/-2` 自动改写成背景类或其他已知类别。


**补充说明：流程对应的现有代码模块**

1. **读取和整理数据**  
   对应 `src/surgical_agent/data/`。其中 parser、媒体解析、数据划分、标签有效性、因果窗口和派生监督合同已有实际实现及测试；VID30/VID31 必须显式加载 `D:\cholec_dataset\repair_manifest.json`，普通原始扫描只读取与 VID 目录同名的官方 JSON。

2. **提取器械运动轨迹**  
   计划对应 `src/surgical_agent/tracking/`。当前 `detector.py`、`associator.py` 和 `predicted_provider.py` 只有占位说明，尚没有可运行的检测或轨迹关联实现。

3. **总结此前的手术流程和保存历史事件**  
   `src/surgical_agent/workflow/contracts.py` 已定义流程状态接口；`src/surgical_agent/research/memory/` 当前主要是占位文件。流程状态与事件记忆在设计上相互独立，但实际存储、更新和检索逻辑尚未实现。

4. **调用大模型完成第一次判断**  
   `src/surgical_agent/api/contracts.py` 已定义通用请求和响应格式，`src/surgical_agent/inference/engine.py` 具备禁止评估真值进入推理的基础边界；实际 API 适配器、缓存、结果解析和基础系统仍未实现。

5. **决定是否需要额外复核**  
   计划对应 `src/surgical_agent/research/gate/`。当前目录中的收益模型、特征、预算和策略文件均为占位文件，不能执行真实决策或训练。

6. **执行复核、更新状态并评估**  
   计划对应 `src/surgical_agent/research/verification/`、`research/reliability/`、`systems/v3_streaming.py` 和 `evaluation/`。这些文件目前基本都是占位说明，尚未形成可运行的复核、可靠性计算、完整流程编排或指标实现。
